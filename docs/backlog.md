# 进度与待办

PoC 阶段结束。本文件记录 PoC 覆盖到的范围、已知的打磨项、已有设计取舍与遗留小项;功能推进顺序见 `todo.md`。

## 一、PoC 覆盖范围

一条完整的链路已经跑通:桌面端连上主机、打开历史会话、看到历史与流式内容、发消息、工具调用、分叉。数据层与协议层是最终形态,界面层是首个可用版本。

能跑的部分:

- **协议**(`packages/protocol`):会话与对话两条通道(另声明 `diff` 与 `terminal`,主机端未实现)、23 个动作、14 个请求,`hello` 握手、序号流、缺口检测
- **主机**(`apps/server`):端点分发、会话表(一文件一份运行态、单飞、同 id 冲突检测)、按订阅持有与空闲回收、事件回放缓冲
- **agent 封装**(`packages/agent`):会话工厂、事件与消息的类型转换、工作目录隔离
- **客户端**(`packages/client-core`):状态归约、去重与缺口补齐、统一投影、全量历史装载、按轮分叉
- **传输**(`packages/transport`):WebSocket,重新握手后可续订并对齐;自动重连尚未接通
- **界面**(`packages/ui` + `apps/desktop`):侧栏(顶部标题栏、新建会话、项目过滤器、时间分组队列、主机状态条、页脚)、对话面板(六种行、收起、Markdown、代码块、文件改动、耗时)、贴底跟随与回底按钮、输入区、排队条、通知

PoC 时的测量:855 条消息、2.6 MB 的会话,投影 + 分行约 3 毫秒;全量装载后滚动高度约 6 万像素。

## 三、已知取舍

- **分叉点在每一轮结束处**:取下一轮开始条目的前一条作为分叉点,这一轮之后追加的用量、改名、压缩条目一并保留;最后一轮分叉取会话末尾
- **过程行摘要**只说这一轮的工作时长,思考段数与工具次数只在展开后可见
- **代码块**是自绘卡片。库自带的代码块把正文渲染在 shadow root 里,样式与折行都无法控制
- **工具卡的成败**只靠颜色区分,不写「完成」「失败」;执行中写「执行中」,被中止而没执行到的写「未执行」
- **历史工具耗时**靠协议补的 `durationMs`;更早的会话文件里没有该字段时,工具卡不显示时间
- **历史分页**只映射窗口内的条目,并且只取活动分支;游标用条目 id,跨进程重启仍然有效
- **回合状态**由主机的 `session/phase` 给出,取值 `idle`、`starting`、`running`、`stopping`;压缩与自动重试记在 `maintenance` 上,两者都由 `session/phase` 一条动作推送
- **两条通道各放一类数据**:会话通道只放状态(`SessionState`:阶段、维护动作、模型、思考档位、标题、队列),对话通道只放内容(`ChatView`:条目、工具调用、提示、标识迁移)
- **界面读一个状态**`chatActivity(session)` 把阶段与维护动作合成 `idle`、`running`、`compacting`、`stopping` 四值,发送与停止按钮按它决定形态;被中止的助手消息按 `stopReason` 在行末标「已停止」
- **动作的持有**`hub.withSession()` 在调用时同步登记持有,归还之前会话不会被空闲回收;显式 `release()` 遇到持有会挂起,等最后一个归还再执行
- **同一会话的动作串行执行**,后到的动作看到前一个动作完成后的状态;`PiAgent.prompt` 在运行开始后即返回,不再等整轮结束,停止请求不会被整轮阻塞
- **撤回消息**在同一个会话里挪分支指针:pi 的会话文件只追加,撤回只是把叶子挪到目标消息的前一条,原文回到输入框,被放弃的一段留在文件里成为另一条分支;不新建会话,跑动中不允许撤回
- **排队消息**走 steering:运行中发送的文本插进当前轮次,排队条列出待插入内容,收回时把文字拼回输入框;followUp 的入口还没做,协议里留了 kind
- **配色**是同一套语义色板的六种取值(浅色加五套深色,缺省 zinc),写在 `theme.css` 的 `data-theme` 选择器里,组件只读同一组变量;代码高亮另选八套,浅深跟随界面主题,单版配色两边共用一份
- **字体**随构建产物一起打进应用:界面 Latin 用 Inter(@fontsource),界面汉字用可变字体 Noto Sans SC(@fontsource-variable),代码的 Latin 与符号用 Maple Mono(packages/ui/src/assets/fonts 下的 woff2,OFL-1.1),代码汉字用 @automann/maple-mono-cn 的 400 分片;所有分片按 unicode-range 只加载渲染到的那几片,系统装没装中文字体都不影响显示
- **设置**分两处:界面偏好与新建会话的默认值在 facet 自己的 settings.json,模型、凭证与提供方配置交给 pi 的 models.json 与 auth.json;两边各管一件事,不互相改写
- **凭证**经 facet 自己的文件实现读写 auth.json:先写盘再让运行态用上,重启之后仍在;密钥只上行,界面只显示是否已配置与来源
- **自定义提供方**就是 models.json 里带模型清单的条目,写完重读模型目录即可用;地址覆写是只有 baseUrl 的条目,两者共用同一份配置
- **界面状态**分两处:窗口位置尺寸存在桌面的 `desktop.json`,外观与新建会话默认值存在主机侧 settings.json,草稿按会话分存在本地;侧栏宽度按方案 B 固定,不再保存
- **主机进程**由桌面主进程拉起,两边共用一个可执行文件,就绪后打印端点、崩溃按退避重启、父进程消失后自行结束;给出 `FACET_ENDPOINT` 时桌面只当客户端连外部主机
- **错误重试**按最后一条用户消息分叉出新会话再重发,新会话里只有一份用户消息,失败的调用留在原会话
- **连接恢复**:退避重连后按序号续订;主机重启过时不认识原会话,按文件重新打开一次,文件也没了才回到空状态
- **项目清单**的每次改动先在副本上做,写盘成功之后才替换内存;整段改动排进同一条队列,失败时界面读到的仍是上一次的结果,临时文件不留
- **添加项目**的返回值直接并进列表,随后的清单刷新失败只标脏,过滤器里给出刷新入口
- **项目目录**在主机侧校验:不存在或不是目录时拒绝,符号链接与 `..` 换成实际路径,同一目录只认一个标识
- **项目信任**沿用 pi 的信任记录:目录里有需要信任的资源时第一次打开前问一次,选择不信任只是不加载项目级扩展、skill 与 MCP 配置
- **项目菜单**只对添加过的项目开放,移除只去掉清单记录;在文件管理器中打开由主机执行,远端主机打开的是它自己的目录
- **会话改名**对已打开的会话改运行态,对没打开的会话离线追加一条会话信息条目,不为此启动 agent
- **删除会话**先释放运行态再删文件,空会话没有文件时按拒绝回执返回
- **会话切换**先打开新的、成功之后才退订旧的,失败时原会话继续可用;会话级操作在同一条队列里执行,快速切换只采用最后一次选择的结果
- **打开失败**退掉已经订上的通道并丢掉半个视图,错误提示带重试入口;会话文件缺失或不是会话文件时给出中文说明
- **发送确认**以主机把消息放进对话(`chat/messageAppended`)或队列(`session/queueChanged` 里出现这段文字)为准,在那之前草稿留在输入框
- **动作被拒**的原因作为一条错误提示写进对话视图:拒绝帧不占通道序号,也不进入归约;草稿留在输入框,可以直接改或重发
- **中止的一轮**里没执行到的工具调用标成「未执行」,内容为空的中止消息不占一行;被中止的助手消息在行末标「已停止」
