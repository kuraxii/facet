# Facet  - UI 设计说明书

本文档提炼了 Facet 侧栏方案 B 的视觉语言、布局规范和组件交互逻辑。本说明书独立于代码实现，可作为向任何技术栈（如 React, Vue, Flutter, 客户端原生）迁移的设计基准。

---

## 1. 设计系统基础 (Design Tokens)

### 1.1 颜色系统 (Color System)
配色是同一套语义色板的六种取值：一套浅色加五套深色，全部以 CSS 变量定义在 `packages/ui/src/styles/theme.css`，组件只读变量。缺省为深色的 `dark`，`跟随系统` 在系统偏浅时用 `light`，否则用 `dark`。

| 配色 | 取向 | 代表色 |
|---|---|---|
| `system` | 跟随系统（设置里排第一位，缺省行为） | 无固定色，按系统取向取 `light` / `dark` |
| `light` | 浅色 | `#ffffff` |
| `dark` | 深色（缺省），中性灰配钴蓝强调色 | `#60a5fa` |
| `midnight` | 深色，蓝调 | `#4a6ba8` |
| `claude` | 深色，暖棕 | `#d97757` |
| `ghostty` | 深色，石板蓝 | `#8caaee` |
| `pureBlack` | 深色，纯黑底 | `#000000` |

每套配色都填满同一组变量，取值含义如下。表里的参考值是 `dark` 与 `light` 两套。

*   **表面背景色 (Surfaces)**：用于构建层级关系。
    *   `--bg`：最底层背景（主视口区）。dark `#18181b` / light `#ffffff`
    *   `--sb`：侧边栏。dark `#131316` / light `#f4f4f5`
    *   `--card` / `--card2`：一级面板与其中的卡片。dark `#1f1f22` / `#27272a`，light `#fafafa` / `#f4f4f5`
    *   `--surface2` / `--surface3` / `--surface4`：悬浮、选中与按下三档。选中的会话行用 `--surface4`
*   **文本颜色 (Text)**：
    *   `--t1`：主文本（标题、正文）。dark `#fafafa` / light `#1a1a1e`
    *   `--t2`：次文本（描述、次要信息）。dark `#a1a1aa` / light `#71717a`
    *   `--t3`：弱文本（占位符、辅助时间/数据）。dark `#71717a` / light `#a1a1aa`
*   **边框与分割线 (Lines)**：
    *   `--line`：常规分割线、边框。dark `#27272a` / light `#e4e4e7`
    *   `--line2`：强调边框（输入框默认边框）。dark `#303036` / light `#ececf1`
*   **语义色 (Semantic)**：
    *   `--acc`：强调色的文字版（链接、聚焦描边、指示条）。dark `#60a5fa`（钴蓝亮版，压深底 7.5:1）/ light `#2563eb`（钴蓝，白底上 5.2:1）
    *   `--acc-fill`：强调色的填充版（主按钮底色），配 `--on-acc` 的文字。dark `#60a5fa`（配深色文字 7.5:1）/ light `#1d4ed8`（比文字版深一档，白字压上去 6.6:1）
    *   `--ok` / `--warn` / `--err`：成功、警告、失败。状态文字与图标用它，底纹用同色的 `--okbg` / `--warnbg` / `--errbg`
    *   `--dot-ok` / `--dot-warn` / `--dot-err` / `--dot-run`：列表行上的状态点。点只有 6pt，彩度比状态色更高一档
*   **Diff 差异色 (Code Diff)**：
    *   `--add` / `--del`：差异文本色。dark `#4ade80` / `#ef4444`，light `#15803d` / `#b91c1c`
    *   `--addbg` / `--delbg`：差异行的底色，取同色 16% 透明度
*   **代码配色 (Code Highlight)**：代码块与差异视图的语法高亮另有一套配色，可选 GitHub、Catppuccin、Dracula、Tokyo Night、One、Nord、Gruvbox、Solarized，浅深跟随界面主题。

### 1.1.1 图标 (Icons)
界面图标与 lucide 一致：`lucide-react` 的 24 栅格线性图标，`size` 12 至 16，笔画 `1.5`，颜色跟随文字变量（`currentColor`）。只导入用到的图标，未用的不进入产物。侧栏页脚的设置入口即 `Settings`。

### 1.2 排版规范 (Typography)
*   **无衬线字体 (Sans-serif)**：`Inter` 与 `Noto Sans SC Variable`（都随构建打包）, 系统默认字体。Latin 与数字用 Inter，汉字与中文标点用 Noto Sans SC Variable。用于常规界面文本。
*   **等宽字体 (Monospace)**：`Maple Mono CN`（400 / 500 / 600，随构建打包）, 等宽字体。用于代码、文件路径、时间、统计数字。必须启用 `tabular-nums`（等宽数字特性）以保证数字宽度一致。
*   **基础字号 (Base Size)**：界面控件 `13px`；对话正文与用户气泡固定 `15px`；整体大小由本机界面缩放控制。
*   **界面缩放 (Zoom)**：本机七档 `80 / 90 / 100 / 110 / 125 / 135 / 150` 百分比，默认 `100`；快捷键 `Mod+=`、`Mod+-`、`Mod+0` 调整，缩放变化后右上角短暂显示当前百分比。
*   **行高 (Line Height)**：基础行高 `1.55`；对话正文与气泡 `1.4`；标题 `1.3`。
*   **对话排版**：正文与气泡同字号同行高；段落之间 `16px`（与 paseo 的 block gap 一致）；行内代码 `0.8em`、`--surface2` 底、圆角 `4px`、无边框；标题按 `1.6 / 1.4 / 1.2 / 1.1` 放大；气泡 `--surface3` 底、内边距 `16px`、圆角 `16px`，右上角收成 `4px`。

### 1.3 尺寸与圆角 (Sizing & Shape)
*   **全局圆角**：小组件（按钮、标签）`6px`，中等组件（弹窗、代码块）`8px`，大组件（输入框）`12px`。
*   **标准行高 (Row Height)**：列表项（工具条、菜单项）标准高度为 `28px`。

### 1.4 交互与动效 (Interaction & Motion)
*   **焦点状态 (Focus Visible)**：所有可交互元素在键盘聚焦时，必须显示 `2px` 的 `Accent` 颜色外发光（Outline），且偏移 `2px`。
*   **动画缓动曲线 (Easing)**：`cubic-bezier(0.2, 0.6, 0.3, 1)`。
*   **动画时长**：颜色/背景色过渡等极快交互 `120ms`；展开/折叠、旋转等位移变化 `180ms`。
*   **阴影 (Shadow)**：弹窗组件使用统一的 Popover 阴影（向下的大范围柔和阴影）。

## 2. 全局布局结构 (Global Layout)

应用采用三栏式网格布局，高度撑满屏幕，内部区域独立滚动。

*   **左侧边栏 (Sidebar)**：固定宽度 `272px`。背景 `Surface 1`。右侧有 `1px Line` 分割。
*   **中栏主工作区 (Main)**：宽度自适应 (`1fr`)。背景 `Surface 0`。
    *   内部内容区（对话和输入框）约束最大宽度 `720px` 居中显示。
*   **右侧面板 (Right Panel)**：固定宽度 `264px`。背景 `Surface 1`。左侧有 `1px Line` 分割。
*   **消息动作 (Message Actions)**：用户消息底部靠右是 `22×22` 的复制与回退，每轮收尾处靠右是复制与分叉，复制都排在左边。按钮无边框、无底色；用户消息上的两个默认隐藏，悬停该行才出现，收尾处的复制与分叉默认可见。只有指针落在按钮本身时该按钮才转强调色，悬停整行不影响。复制成功后图标换成对勾并保持 1.2 秒。
*   **应用外壳 (App Frame)**：去掉系统标题栏。顶部 `--chrome-height`（`36px`）是一条真正的布局行，按下面的三栏切成三格，格子宽度与正文列共用 `--sidebar-width`、`--panel-width` 两个变量，所以顶带里的东西永远和下面的列对齐：
    *   左格：侧栏头部（应用名、搜索会话、添加项目、收起侧栏）；侧栏展开时这一格带侧栏底色与右缘那条分界线，让正文的分隔一直通到窗口顶边；侧栏收起时这一格宽度收到 `0`，头部整个不渲染
    *   中格：左栏开关（`PanelLeft`），只在侧栏收起、或窄屏抽屉未展开时出现，贴在主区左上角
    *   右格：右栏开关（`PanelRight`）、右栏「文件 / 变更」分页、窗口按钮，宽度等于右栏宽度，展开时左缘带一条分界线接上正文的分隔（分隔条悬停时这条线与正文那段一起变色）；右栏收起时这格收到只剩开关与窗口按钮
    *   整条带铺一层 `app-region: drag`，格子里的控件自己标 `no-drag`；双击空白处由 Chromium 处理成最大化切换
    *   窄屏（`880px` 以下）左格宽度为 `0`，侧栏头部改由抽屉自己画
*   **主区域标签栏 (Main Tabs)**：主区顶部一行 `38px`，上下各一条 `--line` 分隔线；左边距 `--main-tabs-edge`（`8px`），标签间距 `--main-tab-gap`（`2px`），单个标签高 `--main-tab-height`（`28px`）。当前标签用 `--surface2` 底与 `--t1` 文字，其余用 `--t3` 文字；横向溢出时只滚动标签，加号固定在后；滚轮落在标签栏上时换算成横向位移（一行标签的滚法：向下滚往后翻），横向手势与缩放组合键不接管，切换标签时把它滚进可见范围。标签可以左右拖到另一条标签的前面或后面，拖动时源标签变淡，目标标签左侧或右侧出现 `--main-tab-drop-width`（`2px`）的强调色竖线。加号菜单目前只有「新建终端」一项。会话、文件、变更、提交与终端标签都可以关闭；关闭按钮在标签悬停或聚焦时显示。会话标签按会话文件区分，文件按项目目录加路径区分，变更文档按项目目录区分，提交按项目目录加提交哈希区分，终端按终端标识区分；同一份内容重复打开时只聚焦已有标签。已打开的会话保留视图与订阅，切回标签立即恢复，不重新请求历史；关闭会话标签后保留 3 分钟再释放。每个会话记住自己的滚动位置，切回时恢复到上次位置。标签上右键打开菜单：关闭、关闭其他、关闭全部、复制路径、复制相对路径；后两项只对文件与补丁标签可用，其余标签置灰。
*   **对话导航 (Chat Outline)**：正文左侧的竖轨，距主区左缘 `--outline-inset`（`8px`，固定值，不随缩放变），宽 `--outline-rail-width`（`36px`），纵向占主区域高度的 10% 到 90%；每条用户消息一根短条，静止 `10×2px`，当前轮次加宽到静止宽度的黄金比例（`16.2px`），指针附近按距离放大到 `22×4px`（半径为 3 条，升余弦衰减，过渡 140ms），加宽与放大叠加时总宽收到轨内宽（`30px`）不溢出；短条的尺寸系列都在 `:root` 里（`--outline-pill-*`），组件只写 `--outline-grow`。整套尺寸按 `--outline-scale` 缩放，倍数来自设置里「对话导航缩放」的百分比（50–200，步长 5，缺省 100）；最小可用宽度按间距加放大后的轨宽现算（`780 + 2 × (8 + 36 × 倍数)`），保证放大后仍然不压正文。悬浮时在竖轨右侧 `2px` 处显示 260px 宽的预览卡，两行截断；条数少于 2 或主区域窄于 868px（100% 缩放时留白放不下间距加轨宽，其余倍数据此现算）时不显示。
*   **右侧栏 (Right Panel)**：宽 `320px`（`260–480` 可拖），左缘 `1px` 分割线外加 `--divider-hit-width`（`6px`）拖拽热区，悬停时把这条分割线染成 `--divider-highlight`；窄屏（`880px` 以下）右栏变浮层、宽度由样式定，此时不给拖拽热区，宽度也不再写回本地存储；分页在顶带右侧那一格里（选中给 `--surface2` 底），正文从顶带下面开始，独立滚动，内边距 8px。
*   **变更页 (Changes)**：顶栏是分支名、`↑N ↓M`、总 `+N −M` 与刷新。下面是按路径分组的目录树：目录行只有折叠箭头与目录名；文件行是文件图标、文件名、`+N −M` 与状态图标（新增/删除/修改/重命名/冲突），二进制显示「二进制」，不显示状态字母。目录不显示增删统计，文件与顶栏显示。点文件在主区域打开或聚焦变更文档，并滚到对应文件；目标文件已折叠时先展开，重复点同一个文件也会重新定位。侧栏不内嵌补丁。
*   **文件页 (Files)**：惰性目录树，行高 22px、左侧 8px 起按层级缩进 12px，目录在前；目录行是箭头与名称，文件行是文件图标与名称，悬停与选中用文字色叠加，加载中给省略号，失败给「读取失败」。打开文件在主区域新增或聚焦文件标签：顶部标题行左右留 `--editor-gutter-x`（`4px`），代码正文贴主区边界，下面是 CodeMirror 6 的只读视图（行号、折叠槽、当前行、换行）。
*   **Markdown 预览 (Markdown)**：`.md` / `.markdown` / `.mkd` 打开后默认显示渲染结果，正文按 `--file-preview-width`（`720px`）居中，窗口窄于它时两侧退到 `--file-preview-gutter-x`（`16px`）；标题行多一个眼睛/代码图标切到源码，光标停在渲染结果上时看的是未保存的草稿，不是磁盘那份。源码视图认 GFM（表格、任务列表、删除线）与围栏代码块的语言，标记符（`#`、`**`、`>`、反引号）退成 `--t3`，行内代码用 `--markdown-code-text`，链接地址与引用也压到 `--t3`，斜体走斜体字形。`.mdx` 不在其中，那是带 JSX 的方言。
*   **编辑态 (Editing)**：文件标签标题栏右侧是铅笔；进入编辑后换成「保存」与退出，未保存时路径后面有一个强调色小圆点。保存成功短暂显示对勾；冲突时在编辑器上方给一行「文件已在磁盘上改动」加「重新加载 / 覆盖」。Markdown 停在预览时点铅笔直接落到源码的编辑态，不用先切一次模式。
*   **提交历史 (Commits)**：变更视图底部一段可折叠列表，默认收起；标题行是折叠箭头、「提交历史」与条数。展开后按新到旧列出全部提交，行内是提交图上的点、短哈希、说明与相对时间；点一条在主区域打开它的改动文档。展开后按内容向上延伸，最高占可用高度的 `60%`，列表自己滚动；收起时只保留底部标题行。不是 git 仓库时不显示。
*   **变更文档 (Changes)**：同一项目只保留一个标签。顶部栏是分支、`↑N ↓M`、总 `+N −M`、全部折叠/展开、自动折行与刷新；正文把所有改动文件放在同一滚动区，每个文件一个 `28px` 吸顶文件头：折叠箭头、文件名、灰色目录、`+N −M` 与状态图标。点文件头折叠/展开该文件；补丁进入视口附近才取，已取到的结果在折叠后保留。补丁行是全宽色带，行号右对齐，长行默认横向滚动，可切换自动折行；二进制、空补丁与截断各有提示。
*   **终端标签 (Terminal)**：新终端在主区域打开一个标签，标签名取启动目录名，悬停显示 shell 与目录；关标签同时结束进程。快捷键 `Ctrl + 反引号` 回到已有终端标签，没有终端时在当前目录新建。终端面板打开或切换标签之后焦点直接进入终端，键盘输入不用再点一次面板区域；面板与标签的滚动条与界面其它地方同一套。
*   **设置窗 (Settings)**：原生 `<dialog>` 打开的一层，尺寸 `min(920px, calc(100vw - 48px))` × `min(660px, calc(100vh - 48px))`，居中，圆角 `16px`，底色 `--card`，左侧分类栏 `148px` 用 `--bg`，右侧内容独立滚动；遮罩是 `::backdrop`，点遮罩或按 Esc 关闭，页面其余部分在打开期间不可交互，焦点由浏览器收在弹层里并在关闭后还给打开它的按钮。分类四页：模型、外观、输入、关于。页内按主题分组：组标题在上，下面是一张卡片，卡片里一行一个设置（左名字、右控件）。外观页「通用」组里依次是主题色板、运行中的动效（呼吸 / 扫光）、减少动效、对话导航缩放（50–200 的百分比，步长 5）。设置没有保存按钮，改动停下 1 秒自动提交，关闭时立刻提交。
*   **模型页 (Models)**：页头一行，左边是标题「模型」，右边是这一页唯一的主动作「添加提供商」（强调色填充，带加号图标）。下面依次是三段：
    *   **默认设置**：一张卡片两行，两行都直接写 pi 自己的设置（`settings.json`），新建会话由 pi 用它开局，facet 自己的设置文件里不再存这两项。上面一行「默认模型」，下拉里只有可用模型（`提供方 / 展示名`），写 `defaultProvider` 与 `defaultModel`；pi 里存的模型已经不在可用范围时也照样列出来。下面一行「默认思考档位」，写 `defaultThinkingLevel`，选「由模型决定」就把这一项清掉。下拉都是 `220px` 宽。
    *   **已配置的提供方**：组标题带条数（`已配置的提供方 · 4`），只列有凭证的与自定义的。整组是一张圆角卡片，行与行之间是一条 1px 发丝线；每行左边是名字首字母的圆牌（`26px`，取强调色 14% 底与强调色文字），名字（自定义的再带一个「自定义」徽标，内置的不加标记）后面直接是「编辑」，一行放下；只有缺密钥时才在「编辑」左边给一个 6pt 的告警色点（`--dot-warn`），密钥配好的行不加任何标记。行里不放密钥、删除这些按钮，状态也不用文字说。
    *   **可用模型**：与上面同一套卡片行，只列已配置提供方的模型；每行是展示名、`提供方 · 模型标识`（等宽）与一个「测试」。测完在「测试」左边给一个状态点：成功取 `--dot-ok` 并在旁边写往返耗时（`240 ms`），失败取 `--dot-warn`，主机给的原话补在来源那行下面。
    *   **添加提供商**：点页头的按钮打开 `520px` 宽的挑选弹窗，顶部搜索框自动聚焦，只列还没配置的提供方并可搜索；每行只有字母圆牌、名字与「添加」，一行放下——点了关掉挑选弹窗，直接打开这个提供方的编辑弹窗填地址与 API key。底部左侧是强调色文字的「＋ 添加自定义提供方」，右侧是「完成」。
    *   **提供方编辑弹窗**：整页是一份草稿——字段改动、密钥的替换与删除都只改本地状态，点底部的「保存」才一起落盘，点「取消」全部丢掉（「删除提供方」是独立的两步确认动作）。`640px` 宽，圆角 `16px`，头部是一行标题（`编辑 · DeepSeek` / `添加自定义提供方`）与关闭按钮，底部是一条带上边框的操作栏，中间正文自己滚，保存与取消不会滚出视野。字段自上而下：自定义提供方先是并排的「名称」与「标识」（标识跟着名字自动推出，改过之后不再覆盖），然后是「接口地址」「接口协议」——内置提供方的地址、协议与模型全由 pi 的目录给定，弹窗里不给这几项，要改地址就新建一个自定义提供方；接下来是「密钥」——一块浅底方框，里面就是一个输入框（右边只有已配置时才出现的「删除密钥」）：已配置时占位提示「输入新密钥以更新」，未配置时占位提示「未配置密钥，输入新密钥以更新」。填了新密钥、或者按下了「删除密钥」，都要等弹窗底部的「保存」才落盘（按下的删除按钮变成错误色、文字改成「取消删除」，再点一下收回）；行内没有自己的保存按钮，密钥区里也没有状态点，配没配由占位提示与删除按钮体现；最后是「模型」。自定义提供方的模型是六列网格（模型标识、展示名、上下文窗口、最大输出、思考开关、移除），表头与每行共用一组列宽，右上角并排「从上游获取」与「添加模型」——「从上游获取」由主机拿上面的地址与密钥去打上游的 `/models`（有的网关要密钥才给列表）：地址是裸站点根时并发试 `{根}/models` 与 `{根}/v1/models`（中转站对未知路径回 200 + 前端 HTML，响应不是模型清单就算失败），成功后把可用地址回填进「接口地址」；拉到的模型用随包的 models.dev 快照补齐展示名、上下文窗口、最大输出与是否思考（同一标识多来源时取厂商官方那条，查不到就留空），已经填过的行不覆盖；内置提供方的模型由 pi 的目录给定，只列出展示名、标识与上下文窗口。自定义提供方的操作栏左侧是「删除提供方」，按一次变「确认删除 / 取消」，右侧是「取消」与「保存」。
    *   各组只留标题，设置项只留名字与控件，不写说明文字；API key 状态、可用状态都由点与按钮本身表达。
*   **响应式规则**：
    *   **宽屏 (`>= 1100px`)**：三栏同时平铺显示。
    *   **窄屏 (`< 1100px`)**：右侧面板默认隐藏。通过主区的“显示文件导航”按钮唤出时，右侧面板以绝对定位抽屉的形式从右侧滑出浮于主视口上方，并附带弹窗阴影。

## 3. 核心模块与组件规范 (Core Modules)

### 3.1 左侧边栏 (Sidebar - 会话与项目管理)
*   **宽度**：缺省 `272px`，右缘一条 `--divider-hit-width`（`6px`）命中区可拖，范围 `220–420`；这 6px 里只有 `--sidebar-hit-inset`（`1px`）压在列表内容上，其余落在接缝外侧的主区，贴右缘的滚动条照旧可点（伸出去的部分靠宽屏下 `.sb` 的 `overflow-clip-margin` 才不被裁掉）。拖动期间直接改 `--sidebar-width`，松手才提交，宽度与顶带左格同步（与右栏同一套逻辑）。默认值、上下限与夹紧口径在 `sidebar-state.ts`（`clampPaneWidth`，与右栏共用），跟着本地存储走，不进主机设置。命中区悬停或拖动时，侧栏自己那条右边线染成 `--divider-highlight`，不加粗也不另叠线；与右栏同一条口径，两边看上去一致。拖动期间根节点挂 `data-resizing="col"`，整页光标统一成列宽光标、文字不可选中，松开或组件卸载时摘掉。
*   **顶部工具栏 (Header)**：应用标题 `Facet` 在左，搜索会话、添加项目、收起侧栏三个图标按钮靠右对齐，按钮边长 `--icon-button-size`（`28px`），这一行上下各 `4px` 让按钮在 `36px` 的顶带里垂直居中，标题与下面的新建按钮、会话行左对齐（都在距侧栏左缘 `10px` 处），按钮距侧栏右缘同样 `--sidebar-edge`（`10px`）；这一行落在窗口顶部那条带里，参与拖动。窄屏抽屉自带一份同样的头部。搜索按钮只负责打开浮窗，输入框不在侧栏里。
*   **核心操作区**：
    *   **新建会话按钮**：占满宽度的强调块。
    *   **项目过滤器 (Project Filter)**：点击弹出下拉列表组件，可全局搜索项目。带有当前项目标签和相关的主机/上下文信息展示。
*   **会话队列列表 (Queue)**：
    *   **分组**：按时间线分组（"进行中", "今天", "昨天", "更早"）。组标题展示组名及数量。日期组按最后活动时间倒序；"进行中"组只按进入先后排，新开跑的一行出现在组首，已经在跑的几行位置不动——主机推来的摘要时间每一轮都会刷新，照着时间排会让同时在跑的会话互相挤。
    *   **列表项 (Row)**：Hover 时叠加 4% 的文字色，Active（当前选中）叠加 8% 的文字色并给标题 500 字重、副标题提到 `--t2`；两者都不用左侧强调条或描边。在会话行上右键打开浮层菜单，菜单出现在指针位置并收进视口，里面是重命名、打开所在文件夹（在主机侧文件管理器里打开该会话的工作目录）与删除；点菜单外或按 Esc 收起。全部项目视图里每行分两行：第一行标题，第二行左边项目名、右边相对时间，字号 `11px`、颜色 `--t3`；单项目视图仍把标题与时间放在一行。两行时行最小高度 `44px`，纵向内边距 `6px`，状态槽对齐第一行。
    *   **状态标记 (Status mark)**：位于列表项左侧的固定槽位（`--status-slot`，`12px` 见方），槽位尺寸不随状态变，标题因此不会左右跳动。五种画法：
        *   运行中：环。三个圆画在一个 SVG 里：闭合的轨道环（30% 透明）、走四分之一圈的弧（90% 透明、圆头端）、中间一个 6pt 的点。半径与描边宽度都从 `--status-ring-*` 算，`cx/cy/r` 当 CSS 属性写；弧的虚线用 `pathLength` 把周长归一成 100 后写成 `25 75`，偏移动画走满 100 正好回到起点。周期 `900ms`，所有环共用文档时间轴的起点，后出现的环与在转的环同步。
        *   等待输入：填色的告警图标（`CircleAlert`，12pt），描边取侧栏底色，圆的轮廓与感叹号从这个颜色里挖出来。
        *   有结果：6pt 填色圆，成功色。
        *   失败：6pt 填色圆，错误色，外面一圈 1pt 透明空隙（`--status-dot-gap`）；空隙透出行自己的底色，行悬停与选中变亮时不会多出一圈暗环。
        *   已完成：6pt 填色圆，中性色加 30% 透明度——弱化但占住左侧导轨，嵌套行不会看起来像项目标题。
        *   颜色直接取 `theme.css` 里的 `--dot-run` / `--dot-warn` / `--dot-ok` / `--dot-err`；`prefers-reduced-motion` 下环不转。
*   **搜索浮窗 (Session Search)**：`⌘K` 或头部搜索按钮打开的一层浮窗，居中偏上（距正文上沿 `12vh`），宽 `min(560px, 100vw - 32px)`，圆角 `12px`，底色 `--card`，1px 描边加一层大阴影；遮罩固定在视口上，连窗口顶部那条带一起变暗，点遮罩关闭。顶部是图标加输入框（自动聚焦、`15px`），下面按改动时间倒序列出匹配的会话，每条是状态点、标题、项目名与相对时间，当前会话的时间用 `--acc`；上下键走、回车打开、Esc 关闭，最多 40 条，无匹配时给一行「没有匹配的会话」。侧栏里的队列不参与过滤，浮窗关掉之后还是完整的一份列表。
*   **底部区域**：
    *   **页脚 (Footer)**：左侧是主机切换按钮，右端是设置，按钮与顶栏同为 `28px`，左缘与正文对齐（距侧栏左缘 `10px`）；不再显示主机名；主机切换点开是主机清单，列出本机与已添加的远程主机，行内是状态点、名字与 `host:port`，底部「添加主机」。关闭窗口后主机一律留在后台，这里不再给开关与结束主机的入口。

### 3.2 主工作区 (Main - 聊天与编辑器)
*   **顶部导航 (Workspace Header)**：
    *   选项卡容器（对话、打开的文件）。支持横向滚动，隐藏滚动条。
    *   全局滚动条：细的悬浮条，没有外框、轨道与两端的箭头，只剩一条 40% 不透明的拇指，指针落上去提亮；需要完全隐藏的地方用 `::-webkit-scrollbar { display: none }` 覆盖。Chromium 给了 `scrollbar-width`/`scrollbar-color` 会改按标准画并带箭头，所以这边只走 webkit 伪元素。所有会滚动的容器都留出沟槽（`scrollbar-gutter: stable`），滚动条出现时内容不左右跳动。
    *   滚动容器统一走 `ScrollArea`（`packages/ui/src/common/scroll-area.tsx`）：类名 `scroll-y` 给滚动行为并始终预留沟槽，行用 `ScrollRow`（类名 `scroll-row`）承担横向留白。Chromium 把滚动条画在容器的内边距里，所以占满一整栏的滚动容器**只留纵向内边距**，横向留白交给每一行，滚动条才能贴着容器右缘；行相对容器边缘的留白由 `--scroll-inset` 给出，右侧再扣掉 `--scrollbar-width`，左右才对称。弹层（命令列表、搜索浮窗、项目选择）不套这个约定：它们的留白跟着弹层自己的内边距走。
    *   当前文件激活时，右侧显示编辑器工具（查看模式切换：预览/内容/改动）。
*   **对话流 (Timeline)**：焦点管理 (Accessibility/Focus)：所有按钮、输入框、树状菜单项必须支持 Tab 键获取焦点。弹出项目切换器时，焦点需限制在弹窗内（Focus Trap），关闭时焦点需恢复到原按钮。
    *   **扩展交互卡片 (Extension Prompt)**：扩展发起的确认、选择、输入与多行编辑都显示为输入区上方的一张卡片，位置在排队条与输入框之间，宽度与输入框一致；背景 `--card`、1px `--line` 描边、圆角 `12px`、内边距 `16px`，不使用遮罩。标题取扩展标题的第一段，其余段落作为正文显示并保留换行。选择请求是单选列表：每行 18px 圆圈，选中时圆圈换成强调色圆点、行底色用 `--surface2`，未选中时「提交」不可用；上下键换选中项，回车或点「提交」提交，Esc 或「关闭」取消。确认只显示正文，输入与多行编辑在标题下方给控件，多行编辑保留完整预填内容与换行。结构化请求在同一张卡片里按题分标签页：标签页写 `header`，缺省时写题号，文字居中；已作答的题目前显示强调色对勾，未作答的题目前显示 `--t3` 的空心小圆点，当前选中未作答时提高不透明度；左右键换题，每题的选项排在标题与正文下面，单选是圆圈、多选是方框，选项说明用小一号的 `--t2` 文字。题目允许自定义答案时，选项列表最后多一行 `Type something.`，选中后这一行原地换成输入框，单选题输入后清空已选选项，多选题与勾选项一起提交。选项带预览时，在选项列表下方用等宽文本块显示当前选中项的预览，未选中时显示第一项；自定义答案激活时隐藏预览。备注输入框排在最后，回车与「提交」一次交出整组答案。卡片底部右侧是关闭与提交两个按钮。只读端与断线时同一位置显示只读卡片，保留请求内容，不给按钮。同一会话有多个请求时按发起顺序逐个展示，前一个结算后自动顶上。
    *   向下滚动，顶部包含会话标题和 Meta 信息。
    *   **长会话**：每条消息行使用 `content-visibility: auto` 与 `contain-intrinsic-size: auto 80px`，离屏行跳布局与绘制；带 `data-outline-key` 的用户行保持正常渲染，保证对话导航跳到真实位置。
    *   **用户气泡 (User)**：包含提示符（`>`）和文字。
    *   **过程行 (Process)**：一次提问里没有正文的那些消息合成一行。收起时是一行：扳手图标 + 标题，标题按这一组做了什么事归类计数，例如「运行了 5 个命令」「编辑了 2 个文件和运行了 3 个命令」；只有思考时是「已思考」。默认收起，收起时没有底色，悬停只让文字由 `--t2` 变到 `--t1`。展开后标题才带 `--surface2` 药丸底、左侧换成朝下的箭头，下面是左侧 `1px` 竖线的缩进区：竖线落在箭头字形的左缘，行内容距竖线由 `--indent-rail-offset` 给出（缺省 `16px`），竖线相对正文列的位置由 `--indent-rail-inset` 给出（缺省 `4px`，来自箭头字形在图标盒子里的内缩）；行首图标边长 `--indent-rail-icon`（缺省 `14px`）、图标到短名的间距 `--indent-rail-gap`（缺省 `8px`），短名列与输出、思考正文的缩进都由这两项相加得到。
    *   **缩进区 (Group Body)**：一行一个动作，行首是 14px 图标（命令、读取、编辑、搜索、其他），接着是短名（Shell、Read、Edit、Grep 等），再往后是等宽字体的参数摘要，单行省略。点这一行才展开输出，输出没有边框与底色，直接缩进在下面；超过 12 行或 1400 字先折起来给「显示全部」。行悬停不加底色：短名默认 `--t2`，悬停或这一行已展开时变 `--t1`。成败只由短名的颜色区分：失败 `--err`，被中止而没执行到 `--warn`；正在执行的这一行由短名与参数摘要上的扫光表示，行尾不加任何标记，也不写状态文字。
    *   **思考行 (Thinking)**：同一组里的一行，大脑图标 + `Thinking`，点开是正文，正文用界面字体。这一轮没有工具调用时它直接落在答复正文里，与 Markdown 左对齐，收起态的悬停与过程组一致（只变文字颜色，没有底色）。
    *   **工具行**：一行只有图标、短名与参数摘要，点开看输出。脚本类工具（`codemode`）短名是 `Codemode`，摘要取脚本第一行有内容的代码；它在脚本里再调用的工具不参与渲染，对话里只剩「一段脚本」这一行，不再被它调用的工具铺满。
    *   **改动不进对话**：工具结果里的补丁不在对话里单独成行，也不画 diff；要看改动走右栏变更页或主区变更文档。
    *   **展开内容**：就是工具结果原文，与模型看到的那份完全一致——`Script completed` / `Wall time` / `Output:` 前缀、多段文字之间的 `==> text N/M <==` 分隔行、`<console_output>` 包裹行都照原样显示，界面不删改任何一行，也不加 `input` / `output` 这类标题。长输出仍按 12 行折叠。
    *   **图片**：工具结果里的图片块直接画在行下面（不进展开区），用 `data:` URL 交给 `<img>`，不落盘、不另起协议。图片进入视口前后 300px 缓冲区内才挂载 `<img decoding="async">`，之前只画 16:9 占位框；按行宽缩放、限高 320px，点一下在原始尺寸与缩放之间切换，超出就在行内横向滚动。文本结果照旧收在展开区里。
    *   **参数摘要**：一行放不下就截断。鼠标在摘要上停留 0.5 秒才用弹窗给出没截断的完整参数（扫过去不弹），脚本类工具给整段代码；摘要没被截断时不弹。弹窗铺在窗口上（`position: fixed`），不参与行内排版；参数长过弹窗高度时可在弹窗里滚动，指针移进去不会收起，离开 0.3 秒后才关。
    *   **流式状态**：回合还在跑时，组标题与正在执行的工具行用同一套动效表示在跑，落在文字上，不再另加状态点。只要会话仍在推进，组标题就持续播动效——两次模型调用之间、工具执行期间没有流式项时也不停。缺省是呼吸：文字保持 `--t1`，`opacity` 在 0.45 与 1 之间按 `--live-cycle`（1.6s）循环（只改不透明度，由合成器执行，文字不参与重绘）。设置里把「运行中的动效」改成「扫光」后换成 `background-clip: text` 的渐变带扫过（`--t2` 打底、`--t1` 作亮带），同样按 `--live-cycle` 循环，观感更明显，但逐帧重绘文字。会话状态点的闪烁也取同一个 `--live-cycle`，场上的几处动效步调一致。两种都随回合结束即停；`prefers-reduced-motion: reduce` 下都不播动画，文字停在 `--t1`。
    *   **上下文摘要**：压缩期间在消息流末尾显示图标与「上下文摘要」，两侧是分界线，文字使用运行中的动效设置，减少动效时保持静止。压缩条目按 `Entry.id` 固定位置，显示为同名分界，默认收起；点击或用键盘展开后显示完整 Markdown 摘要。历史记录与实时记录共用这一显示方式，多次压缩各自保留分界。取消或失败时收起动效行，完成分界只来自已有的压缩条目。
    *   **富文本 (Prose)**：支持 Markdown 渲染和行内代码块。
    *   **代码块 (Code)**：带有语言标签和“复制”功能（Hover唤出），支持语法高亮。
    *   **变更总结 (Changes)**：展示文件修改的统计（新增行数、删除行数）。
    *   **收尾行 (Turn Footer)**：这一轮结束时一行，左起复制、分叉，右边写这一轮的工作时长，格式与 paseo 一致：`工作了 7s`、`工作了 3m 16s`、`工作了 1h 5m`；还在跑时由界面自己计时。
*   **错误提示 (Error)**：一层 `--errbg` 浅底、圆角 6px、内边距 12px 10px，不描边；左上是 16px 的圆形警示图标，固定在列首不参与收缩，不写「出错」二字。正文用 `--t1` 与正文字号，`overflow-wrap: anywhere` 让长串报错（JSON、请求标识）在任意位置断开。动作是「重试」与「复制详情」两个文字按钮，排在正文下方，悬停转 `--t1` 并加下划线。
*   **输入框区域 (Composer)**：
    *   固定在页面底部。
    *   **引用区域 (File Reference)**：如在代码中选择了某几行，会在输入框上方显示引用的文件和行号标签。
    *   **输入框 (Textarea)**：外边框为 `Line Strong`。聚焦时边框变为 `Accent`，并增加发光阴影环。高度两行起步，跟着内容向上长，最多十四行；再多就在框内滚动，滚动条与界面其它滚动区同一套。
    *   **操作栏**：左侧是「+」添加菜单与两个芯片——模型芯片显示模型名，思考芯片显示大脑图标加档位取值（Off 到 Max，不翻译）；两个芯片默认没有底色，悬停或展开时才有 `--surface2` 底与下拉箭头（收起朝下、展开朝上）。右侧是上下文用量环与一个 34×34 的主按钮：有内容要发时是发送箭头（运行中即排队），这一轮在跑而没有内容可发时换成停止——同一个方框、同样的 10px 圆角，中间换成红色方块，两种形态互相替换，位置不动。

### 3.3 编辑器视图 (File View)
如果激活了文件选项卡，主区的内容替换为代码编辑器。
*   **行号区**：固定在左侧，等宽数字，文本颜色较弱。
*   **源代码区**：横向防溢出。支持 `token` 级别的语法高亮（Keyword, String, Number 等）。Markdown 按 GFM 解析，围栏代码块内嵌语言着色。
*   **Markdown 预览**：`.md` 的默认形态，渲染交给对话区同一套 `markstream`，只是不出流式动画；编辑仍然只发生在源码视图。
*   **Diff 模式**：差异行整行背景色变更（绿底/红底），并在行号旁用 `+` 或 `−` 标识。
*   **底部信息栏**：绝对路径面包屑，所属节点，语言，编码，以及只读状态。

### 3.4 右侧面板 (Panel - 工作区文件)
*   **顶部 Tabs**：在“文件 (Files)” 和 “改动 (Changes)” 之间切换。带徽标数字提示。
*   **项目信息**：当前项目名与所属主机。
*   **文件树 (File Tree)**：
    *   带有即时过滤的搜索输入框。
    *   层级缩进公式：`padding-left = 4px + (深度 * 12px)`。
    *   文件夹前带三角 Chevron 图标（展开时旋转 90 度）。
    *   被修改过的文件右侧带黄色的“已修改”标签。
    *   支持键盘上下箭头导航，Enter/Space 展开或打开文件。
*   **改动列表 (Changes List)**：
    *   平铺展示被修改的文件。
    *   显示独立的新增 (`+42`) 和删除 (`-18`) 的等宽数字统计。

### 3.5 轻提示 (Toast)
操作结果与后台事件的临时反馈，用完即走，不打断当前活动。

*   **位置与容量**：固定右下角，离窗口右、下各 `--toast-edge`（`16px`）；宽 `--toast-width`（`320px`），新的排在下面，最多同时 3 条，超出的丢最旧的。整块只占自己的盒子，空白处不挡鼠标。
*   **等级靠样式表达**：左侧 `3px` 色条与行首图标区分——成功取 `--dot-ok`、告警取 `--warn`、失败取 `--err`，信息用中性色；文字只写事实（哪份文件、什么原因、谁的退出），不写「错误」「成功」「失败」这类标签。
*   **内容**：同一句话重复出现只留一条，右侧浮现次数；长文本折行，不撑破 `320px`。
*   **不带操作**：提示只说事实，要动手的事回原来的地方做（比如再点一次加号菜单新建终端）；右上角只留一个关闭按钮。
*   **计时**：成功 `3s`、信息 `3.5s`、告警 `5s`、失败 `6s`。指针停在提示上或焦点落在按钮上时暂停，离开时补回暂停的时长；每条都能点右上角的关闭按钮立刻收掉。
*   **进动效**：从下方 `6px` 处淡入，`160ms`；`prefers-reduced-motion` 时只留淡入。
*   **可访问性**：整块是 `role="status" aria-live="polite"`，读屏在空闲时念一遍，不抢焦点。
*   **谁用它**：用户动作的回执（复制、开终端失败）与后台事件（主机侧的 `chat/notice`、pi 插件 `ctx.ui.notify`）。需要用户决策的走弹层，需要一直看得见的走页脚，可重试的关键失败走错误条。
*   **层级**：`z-index: 50`，低于右键菜单（`70`）、弹窗（`60`）与悬浮提示（`90`）；原生 `<dialog>` 打开时提示会被顶层压住，此时不弹。

## 4. 关键交互状态要求 (Interaction Guidelines)

设计实现时必须保证以下交互逻辑的完整性：

1.  **组件溢出 (Overflow)**：文件路径、项目名称等长文本必须处理文本截断，统一使用单行省略号 (`text-overflow: ellipsis`)。
2.  **状态互斥 (State Toggling)**：
    *   设置页里的主题会改写根节点的 `data-theme`，配色按此选择变量组；代码配色同时随深浅切换版本。
    *   右面板的隐藏与显示会改变整体 Grid 的列数分配或触发弹窗定位。
    *   对话输入时的“引用文件”，可通过在代码编辑器中点击行号（支持 Shift 多选）触发引用标签生成。
3.  **浮出层定位 (Popover Positioning)**：项目选择下拉菜单需自动计算上下可用空间。如果底部空间不足且顶部空间充足，菜单应当向上弹出（底对齐），防止遮挡视口。
