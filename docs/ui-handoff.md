# 聊天界面交接说明

这份文档给界面设计师使用,说明对话界面现在是什么样、数据从哪来、后续用哪些渲染库,以及需要设计师产出什么。实现细节以代码为准,本文只写界面相关的部分。

## 一、应用形态

一套界面代码(`packages/ui`)同时服务三个客户端:桌面(Electron)、Web、手机。现在只有桌面端接通并跑起来,Web 与手机只有壳。

界面不碰文件系统、不碰 Node、不碰 Electron。它拿到的是已经规约好的视图数据,发出的是意图(发送、停止、审批、分叉),经 WebSocket 送到设备进程。设计师可以把界面当成纯前端看待。

## 三、对话行的数据模型

对话区的一切都是**行**。数据侧把消息归一成渲染单元,渲染侧再把单元聚合成行。行有六种:

| 行 | 来源 | 现在显示 | 交互 | 需求编号 |
|---|---|---|---|---|
| 用户行 | 一条用户消息 | 角色「我」+ 正文 | 收起、从这条分叉 | FR-CHAT-09 |
| 助手行 | 带正文的助手消息 | 角色「助手」+ 正文 + 该消息里的工具卡 | 收起、复制 | FR-CHAT-10 |
| 过程行 | 连续的无正文助手消息(只有思考与工具调用) | 一行摘要「思考 N 段 · 工具 M 次 · 耗时」,展开是思考段与工具卡 | 收起(默认收起) | FR-CHAT-06 / 07 |
| 文件改动行 | 工具结果里的补丁(`edit` 工具) | 「文件路径 +新增行 −删除行」,展开是着色补丁 | 收起(默认收起) | FR-CHAT-06 / 08 |
| 错误行 | 失败的助手回合 | 「出错」+ 错误信息 | 收起 | FR-CHAT-13 |
| 分界行 | 压缩摘要、分支摘要、系统提示 | 居中一行说明 | 无 | FR-CHAT-15 / 16 |

### 一轮对话的行序

```
用户行
过程行        ← 模型思考、调工具，可能有很多次
助手行        ← 正文，这一轮的答复
文件改动行 ×N ← 这一轮改了哪些文件，收在正文之后
```

规则是「正文是过程行的边界」:一条助手消息只要有正文,它就是答复行;没有正文的连续消息都归进过程行。一轮里模型可能调几十次工具,所以过程行可以非常大——现在真实数据里最大的一条收了 33 段思考与 62 次工具调用。

### 一行的内部结构

```
行头:  [▾] 角色标签  摘要文字  [运行中]        [操作按钮]
行体:  正文段 / 思考段(可折叠) / 工具卡(可折叠) / 补丁
```

- 行头的三角按钮负责整行收起
- 摘要文字在收起时显示内容预览,展开后不重复显示
- 收起状态按行标识保存在界面内,流式追加内容不会把用户收起过的行弹开

## 四、现在已经能做的事

- 列出会话、打开会话、看到历史(现在按页加载,每页 40 条,需手动点六次才能看全)
- 发送消息、流式显示思考与正文、停止运行
- 工具调用显示为卡片,带名称、状态、耗时、参数与输出
- 编辑类工具的补丁显示为文件改动行
- 收起与展开任意行
- 从任一用户消息分叉出新会话
- 应答工具审批(允许 / 拒绝)
- 断线重连、缺口检测与自动补齐(用户无感)

## 六、渲染库选型

对话区要用到的外部库,以及各自负责什么。

| 库 | 用途 | 接入点 | 现状 |
|---|---|---|---|
| `markstream-react` | 正文 Markdown 渲染,支持流式未闭合内容 | 助手行的正文段 | 已接入 |
| `stream-diffs` | Markstream 的代码块后端,提供代码块外框、工具栏、行号 | 正文里的代码块 | 已接入 |
| `mermaid` | 正文里的 ```mermaid 图 | Markstream 的可选后端 | 已安装,按需加载 |
| `katex` | 公式 | Markstream 的可选后端 | 已安装,按需加载 |
| `shiki` + `stream-markdown` | 非 Markdown 文本的高亮:工具输出、补丁、日志 | 工具卡输出、文件改动行的补丁 | 未接入,现在是纯等宽文本 |
| `zustand` | 界面状态:收起集合、滚动位置、草稿、面板开合 | `packages/ui` | 已声明未使用,收起状态仍在组件内 |

### markstream-react

```tsx
import MarkdownRender from "markstream-react";
import "markstream-react/index.css";

<MarkdownRender content={markdown} final={isDone} fade={false} />
```

- 输入是**整段 Markdown 字符串**加一个「是否已结束」的布尔值,流式期间把增量累加进字符串重渲染,未闭合的代码块、表格、链接会按进行中状态展示
- 自带样式文件必须显式引入;Tailwind 项目可引入 `index.tailwind.css`
- 代码块由 `stream-diffs` 接管(带语言标签的头部、工具栏、行选择);没装时降级成 `<pre>`
- `mermaid`、`katex` 是可选的 peer 依赖,装上即启用;KaTeX 还需要引入 `katex/dist/katex.min.css`
- 支持自定义组件映射,可用于把 `[文件](path)` 之类的标记换成应用自己的胶囊
- 流式期间 `final` 为 `false`、结束后置 `true`,这个切换点决定了「进行中」与「固化」两种外观

对设计的影响:代码块、表格、引用块、列表这些外观最终由这个库决定,设计师需要给出**主题配色与字号**,而不是画每一个元素;mermaid 图与公式的外框、失败降级样式需要单独设计。

### shiki 与 stream-markdown

工具输出经常是日志、JSON、补丁,不是 Markdown。`stream-markdown` 是 Shiki 之上的流式高亮工具,用来给这些块上色:

```ts
import { createHighlighter } from "shiki";
```

补丁行现在按行首的 `+` / `-` 着色,还没有语法高亮;接入后要保持在流式追加时的稳定(已渲染行不重新解析)。

### zustand

界面状态现在用 `useState` 存在组件里,量还小。下列状态会多到需要单独的 store:

- 每行的收起状态(按行标识)
- 滚动是否跟随底部
- 每个会话的输入草稿
- 侧栏宽度、折叠状态
- 面板开合(差异侧栏、任务面板)

这些都只属于界面,不进数据层的视图。

## 七、技术约束

设计稿落地时不能违反的几条:

1. `packages/ui` 不能引入 `electron`、`node:*`;界面组件必须能在浏览器里跑,因为 Web 端复用同一套
2. 界面不自己解析协议动作,只消费规约好的视图与渲染单元
3. 行标识必须稳定:流式追加、收起、滚动位置都靠它,不能用数组下标当标识
4. 深色是默认,浅色要单独验证:现有色值是硬编码的深色,浅色主题需要一套完整变量

## 九、需要设计师产出

1. **状态矩阵**:每个区域在「空 / 加载 / 出错 / 运行中 / 长内容」下的样子。至少覆盖:对话区为空、历史加载中、连接失败、流式中、流式中途停止、工具失败、补丁很大、超长正文、超长工具输出、审批等待。
2. **行规格**:六种行的行高、内边距、缩进层级、行头结构、摘要截断规则、收起与展开的过渡。
3. **主题**:深色与浅色两套完整变量(底色、卡片底、边框、三级文字、四种状态色、代码块配色)。
4. **代码块与表格**:这两者外观由 markstream 决定,需要给出主题映射与容器规格(最大高度、横向滚动、复制按钮位置)。
5. **图表与公式**:容器、失败降级(显示源码)、加载中的占位。
6. **输入区**:多行、附件、`@` 补全弹层、斜杠命令弹层、排队消息条、模型与思考档位选择。
7. **侧栏**:分区、会话行(标题、时间、状态点)、悬停菜单、宽度拖拽、折叠态。
8. **动效**:流式输出的节奏、行出现与收起、回底按钮、状态点跳动。要给出「减少动效」偏好下的替代。
9. **交互标注**:哪些地方可点、点击后发生什么、悬停显示什么、快捷键。

## 十、待定问题

- 一轮对话的「收尾行」(耗时、改动统计、跳转差异侧栏)要不要合并进文件改动行,还是单独一行
- 过程行默认收起;过程很长时是否显示进度(第 N 次工具调用、当前工具名)
- 工具卡展开后的输出是纯文本还是带高亮;长输出是滚动还是「显示全部」
- 分叉点放在用户行(现在)还是也放在助手行
- 流式期间是否显示「正在思考」与「正在调用工具」的实时文字,还是只靠过程行的摘要变化
