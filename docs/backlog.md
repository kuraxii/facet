# 进度与待办

PoC 阶段结束。本文件记录 PoC 覆盖到的范围、已知的打磨项,以及后续功能推进的顺序。

## 一、PoC 覆盖范围

一条完整的链路已经跑通:桌面端连上设备、打开历史会话、看到历史与流式内容、发消息、工具调用与审批、分叉。数据层与协议层是最终形态,界面层是首个可用版本。

能跑的部分:

- **协议**(`packages/protocol`):两条通道、22 个动作、10 个请求,`hello` 握手、序号流、缺口检测
- **设备**(`apps/server`):端点分发、会话表(一文件一份运行态、单飞、同 id 冲突检测)、引用计数回收、事件回放缓冲、审批中转
- **agent 封装**(`packages/agent`):会话工厂、事件与消息的类型转换、工作目录隔离
- **客户端**(`packages/client-core`):状态归约、去重与缺口补齐、统一投影、全量历史装载、分叉
- **传输**(`packages/transport`):WebSocket,断线重连后续订与对齐
- **界面**(`packages/ui` + `apps/desktop`):侧栏会话列表与搜索、新建会话、对话面板(六种行、收起、Markdown、代码块、文件改动、耗时)、输入区、审批条、通知

真实数据规模:855 条消息、2.6 MB 的会话,投影 + 分行约 3 毫秒;全量装载后滚动高度约 6 万像素。

## 三、已知取舍

- **分叉点**是「包含这条用户消息」,新会话末尾是这条待回答的提问;另一种做法是分到它的上一条,用来重答
- **过程行摘要**只说这一轮的工作时长,思考段数与工具次数只在展开后可见
- **代码块**是自绘卡片。库自带的代码块把正文渲染在 shadow root 里,样式与折行都无法控制
- **工具卡的成败**只靠颜色区分,不写「完成」「失败」;执行中仍写「执行中」
- **历史工具耗时**靠协议补的 `durationMs`;更早的会话文件里没有该字段时,工具卡不显示时间
- **`entries` 每次全量映射**:845 条 0.4 毫秒,暂不是瓶颈
