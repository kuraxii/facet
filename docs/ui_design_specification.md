# Facet  - UI 设计说明书

本文档提炼了 Facet 侧栏方案 B 的视觉语言、布局规范和组件交互逻辑。本说明书独立于代码实现，可作为向任何技术栈（如 React, Vue, Flutter, 客户端原生）迁移的设计基准。

---

## 1. 设计系统基础 (Design Tokens)

### 1.1 颜色系统 (Color System)
配色是同一套语义色板的三种取值：GitHub Copilot 默认浅色（`light`）、GitHub Copilot 默认深色（`dark`），外加一套暖棕深色（`claude`），全部以 CSS 变量定义在 `packages/ui/src/styles/theme.css`，组件只读变量。缺省为深色的 `dark`，`跟随系统` 在系统偏浅时用 `light`，否则用 `dark`。

| 配色 | 取向 | 代表色 |
|---|---|---|
| `system` | 跟随系统（设置里排第一位，缺省行为） | 无固定色，按系统取向取 `light` / `dark` |
| `light` | GitHub Copilot 浅色（Primer Light） | `#ffffff` |
| `dark` | GitHub Copilot 深色（缺省，Primer Dark） | `#1f6feb` |
| `claude` | 深色，暖棕 | `#d97757` |

每套配色都填满同一组变量。变量按**角色**分组，不按颜色分组：同一个组件在三套配色下读同一批名字，换主题只换取值。

*   **表面海拔 (Elevation)**：四档，越靠近用户越靠前一档。
    *   `--bg-canvas`：最底层工作台与主区背景。dark `#0d1117` / light `#ffffff`
    *   `--bg-subtle`：侧栏与次级结构区。dark `#151b23` / light `#f6f8fa`
    *   `--bg-surface`：面板、卡片、输入区与气泡容器。dark `#151b23` / light `#ffffff`
    *   `--bg-elevated`：弹层、下拉菜单、嵌套卡片，**必须不透明**。dark `#212830` / light `#f6f8fa`
*   **交互态 (Interaction)**：全仓只有两个交互底色，由各主题自己的前景色按比例混出，不再为每处悬停各调一档。
    *   `--bg-hover`：列表行与透明按钮的悬停底色（dark 7% / light 6%）
    *   `--bg-active`：选中、按下与展开态（dark 14% / light 12%）；侧栏选中行、设置导航选中项、工具条 `is-on` 都用它
*   **前景文本 (Foreground)**：
    *   `--fg-default`：主文本（标题、正文）。dark `#f0f6fc` / light `#1f2328`
    *   `--fg-muted`：次文本（描述、次要信息）。dark `#9198a1` / light `#59636e`
    *   `--fg-subtle`：弱文本（占位符、辅助时间/数据）。dark `#767e88` / light `#6e7781`
*   **边框 (Borders)**：
    *   `--border-subtle`：结构分割线、面板隔断，永远比控件边框淡一档。dark `#2a313c` / light `#e0e6eb`
    *   `--border-default`：控件边框（按钮、输入框、卡片），浮层阴影里那条 1px 环也用它。dark `#3d444d` / light `#d1d9e0`
    *   `--border-focus`：键盘焦点环与输入区聚焦描边，与 `--accent-fg` 同色
*   **强调色 (Accent)**：
    *   `--accent-fg`：强调色的文字版（链接、强调图标、指示条）。dark `#4493f8` / light `#0969da`
    *   `--accent-fill`：**所有高优先确认主按钮唯一的底色**（发送、添加提供商、保存、对话框确认），配 `--accent-on-fill`（`#ffffff`）的前景。dark `#1f6feb` / light `#0969da`
    *   `--accent-fill-hover` / `--accent-fill-active`：悬停与按下，按各主题自身的前景色混出（浅色主题越点越深，深色主题先亮后暗），不用 `filter` 或 `opacity` 临时提亮
    *   `--accent-on-fill`：主按钮上的文字与图标
*   **状态色 (Status)**：
    *   `--status-ok-fg` / `--status-warn-fg` / `--status-err-fg`：成功、警告、失败的状态文字与图标
    *   `--status-warn-bg` / `--status-err-bg`：状态浅底
    *   `--status-warn-border`：警告类提示的描边
    *   `--dot-ok` / `--dot-warn` / `--dot-err` / `--dot-run`：列表行上的状态点。点只有 6pt，各配色按自身色板微调
*   **Diff 差异色 (Code Diff)**：
    *   `--diff-add-fg` / `--diff-del-fg`：差异文本色。dark `#3fb950` / `#f85149`，light `#1a7f37` / `#cf222e`
    *   `--diff-add-bg` / `--diff-del-bg`：差异行的底色
*   **代码区 (Code)**：
    *   `--code-block-bg`：代码块与行内代码的底色。dark `#151b23` / light `#f6f8fa`。不叫 `--code-bg`：`--code-*` 是 markstream 渲染器在自己根节点上自带的一整套变量，色板用同名会让「把主题值桥接进渲染器」变成自我引用
    *   `--code-block-fg`：代码块与行内代码的文字色。dark `#f0f6fc` / light `#1f2328`
*   **阴影与遮罩 (Shadow & Scrim)**：明暗分治，组件不再自己写 alpha。
    *   `--shadow-control`：内容卡片、输入区与气泡的极轻压边与顶部受光高光（浅色 `0 1px 2px 0 rgb(31 35 40 / 5%), inset 0 1px 0 0 rgb(255 255 255 / 60%)`，深色 `inset 0 1px 0 0 rgb(255 255 255 / 4%), 0 1px 2px 0 rgb(1 4 9 / 40%)`）
    *   `--shadow-popover`：菜单、悬浮提示、轻提示这一层的柔影；浅色轻透，深色叠一条 `1px` 轮廓环（`--border-default`）。浮层不再另写 `border`，否则边缘会叠成两圈
    *   `--shadow-modal`：搜索层、设置窗、对话框与抽屉这一层的大范围投影
    *   `--scrim-bg`：模态遮罩。dark `rgb(1 4 9 / 56%)` / light `rgb(31 35 40 / 28%)`
    *   `--selection-bg`：选中文字的高亮，取 `--accent-fill`（`claude` 取 `--accent-fg`）混出
*   **代码配色 (Code Highlight)**：代码块与差异视图的语法高亮另有一套配色，可选 GitHub、Catppuccin、Dracula、Tokyo Night、One、Nord、Gruvbox、Solarized，浅深跟随界面主题。

### 1.1.1 图标 (Icons)
界面图标与 lucide 一致：`lucide-react` 的 24 栅格线性图标，尺寸只有 `12 / 14 / 16` 三档（`ICON_SIZE.sm/md/lg`，对应 `--icon-sm/md/lg`），描边宽度只有 `--icon-stroke-width`（`1.8`）一处真值，颜色跟随文字变量（`currentColor`）。只导入用到的图标，未用的不进入产物。侧栏页脚的设置入口即 `Settings`。

### 1.2 排版规范 (Typography)
*   **无衬线字体 (Sans-serif)**：`Inter` 与 `Noto Sans SC Variable`（都随构建打包）, 系统默认字体。Latin 与数字用 Inter，汉字与中文标点用 Noto Sans SC Variable。用于常规界面文本。
*   **等宽字体 (Monospace)**：`Maple Mono NF`（400 / 600，随构建打包）, 等宽字体。用于代码、文件路径、时间、统计数字，以及只读的标识展示（如可用模型行里的 `提供方 · 模型标识`）。必须启用 `tabular-nums`（等宽数字特性）以保证数字宽度一致。字体只带 Latin、符号、框线与 Nerd Font 图标，不含汉字：等宽语境里的汉字由字体栈第二位的界面中文字体接手，按比例宽排（一个汉字约一个字号宽，不再等于两个等宽字符）。
*   **配置界面的字体**：设置窗与提供方弹窗里的输入字段一律用界面字体，包括标识、接口地址、密钥与数字；等宽只在只读展示上出现。同一张表单里输入框混着两种字体，看着像两种控件。
*   **基础字号 (Base Size)**：六档字号与四档行高见 `docs/visual-system.md`。界面外壳 `13px`（`--text-ui`）；对话正文与用户气泡固定 `14px`（`--text-body`）；整体大小由本机界面缩放控制。
*   **界面缩放 (Zoom)**：本机七档 `80 / 90 / 100 / 110 / 125 / 135 / 150` 百分比，默认 `100`；快捷键 `Mod+=`、`Mod+-`、`Mod+0` 调整，缩放变化后右上角短暂显示当前百分比。
*   **行高 (Line Height)**：控件与普通正文落在 `20px` 基线（`--leading-ui`）；对话正文、气泡与 Markdown 长文都是 `24px`（`--leading-prose`）；标题 `32px`（`--leading-display`）。代码区例外，走比例行高 `--leading-code-block`（`1.6667`）与 `--text-code-inline`（`0.9285em`），跟着编辑器字号一起缩放。
*   **动效 (Motion)**：四档时长（`--dur-fast` / `--dur-slow` / `--dur-enter` / `--dur-structural`）配五条方向性曲线（`--ease-standard` / `--ease-out` / `--ease-in` / `--ease-enter` / `--ease-panel`）；减少动效与拖窗口/拖分栏期间四档时长一起清零，全仓过渡退回瞬变。细则见 `docs/visual-system.md` §1.7 与 §6。
*   **折叠体**：思考、工具输出与过程组收起时留在 DOM 里并标 `hidden="until-found"`，`Ctrl+F` 命中即自动展开；展开箭头是一枚 chevron 转 90°。
*   **对话排版**：正文与气泡同字号同行高（`--text-body` / `--leading-prose`）。竖向节奏只走下边距：段落、列表、引用、表格卡片与代码卡一律 `margin-bottom: var(--space-6)`，容器首尾用 `> :first-child` / `> :last-child` 贴边，相邻两块不叠加。表格采用圆角卡片容器配水平行分隔线，不画四周全网格。行内代码 `0.8em`、`--bg-elevated` 底、`--radius-sm`、无边框；标题按 `1.6 / 1.4 / 1.2 / 1.1` 相对正文放大（保留 `em`，跟着正文缩放）。气泡 `--bg-surface` 底、四角统一 `--radius-xl` 对称圆角、`1px` 渐变边框 `--bubble-rim` 与柔和底影 `--shadow-bubble` 撑出轻微悬浮立体感、`--bubble-padding-y` / `--bubble-padding-x`（6px / 14px）。气泡的内边距不复用 `--space-8`，那个刻度是代码块与 Markdown 段落的留白。

### 1.3 尺寸与圆角 (Sizing & Shape)
*   **全局圆角**：五档（`--radius-sm` `4px` / `--radius-md` `6px` / `--radius-lg` `8px` / `--radius-xl` `12px` / `--radius-pill` `999px`）的定义与用途见 `docs/visual-system.md` §1。按钮、输入框、列表行、代码块与侧栏行取 `--radius-md`；卡片、工具提示、内联表单取 `--radius-lg`；弹层容器（搜索层、设置窗、提供方窗、对话框）与输入区取 `--radius-xl`；胶囊徽标、状态点与整圆按钮取 `--radius-pill`。
*   **标准行高 (Row Height)**：列表项（工具条、菜单项）标准高度为 `--control-sm`（`28px`）。
*   **控件几何 (Controls)**：按钮、图标按钮、输入框、列表行与徽标的变体、档位与尺寸矩阵见 `docs/visual-system.md` §3；业务样式表只覆盖外边距、定位与领域配色。

### 1.4 交互与动效 (Interaction & Motion)
*   **焦点状态 (Focus Visible)**：所有可交互元素在键盘聚焦时，必须显示 `2px` 的 `Accent` 颜色外发光（Outline），且偏移 `2px`。
*   **动画缓动曲线 (Easing)**：`cubic-bezier(0.2, 0.6, 0.3, 1)`。
*   **动画时长**：颜色/背景色过渡等极快交互 `120ms`；展开/折叠、旋转等位移变化 `180ms`；左右栏与抽屉等外壳结构开合 `320ms`（`--dur-structural` 配 `--ease-panel`）。
*   **阴影 (Shadow)**：弹窗组件使用统一的 Popover 阴影（向下的大范围柔和阴影）。

## 2. 全局布局结构 (Global Layout)

应用采用三栏式网格布局，高度撑满屏幕，内部区域独立滚动。

*   **左侧边栏 (Sidebar)**：宽 `220–420px`（缺省 `272px`）。背景 `Surface 1`。右侧有 `1px Line` 分割。右缘的拖拽条缩到「最小宽再往里一半」（`<= 110px`）就进入待关闭态：侧栏**拖动中当场收到 `0` 宽**，正文实时补位，同时窗口左缘留一条 `6px` 强调色竖线当提示（从窗口上缘一直画到底，顶带那一段由顶带左格自己画，两段同色接成一条）；不松手拉回阈值之外立刻重新展开并继续跟手，松手才真的关掉。收起的宽度不落盘，再打开还是原来那份偏好宽（口径见 `docs/layout.md` §3 约束 2.1）。
*   **中栏主工作区 (Main)**：宽度自适应 (`1fr`)。背景 `Surface 0`。这一列只有对话：消息流与输入区直接撑满，主区里没有标签栏，也没有任何「在主区打开文档」的路径（口径见 `docs/layout.md` §1.1）。
    *   内部内容区（对话和输入框）最宽 `--chat-column-max`（`840px`）。横向是三列网格：左留白 `minmax(--chat-rail-gutter, 1fr)`、正文 `minmax(0, --chat-column-max)`、右留白 `minmax(--chat-rail-gutter, 1fr)`。两侧用同一个下限、同一个 `1fr`，所以**输入框与正文到窗口左缘、右缘的间距在任意宽度下都相等**；右留白里放得下导航轨（`--chat-rail-gutter = max(--chat-gutter-min, --outline-slot)`），竖轨贴在右留白的远端，既不压正文也不破坏对称。窗口不够宽时两侧一起退到下限、正文自己收，**数学上不可能与导航轨重合**。没有导航内容时两侧退回 `--chat-gutter-min`，留白更小但仍对称。消息列与输入区共用这套轨道，左右边缘严格对齐。正文最小可用宽 `--main-min`（`520px` = 52 + 416 + 52），低于它按 `docs/layout.md` 的档位折叠边栏，不靠挤压边栏腾地方。聊天主滚动区**没有可见滚动条**，滚动进度由上下两端 40px 的渐隐提示（其余区域的细滚动条不变）。
*   **右侧工作区 (Workspace)**：宽 `≥ 300px`（缺省 `420px`，没有固定上限——最宽能到多少由正文的最小可用宽现算：视口扣掉左栏与 `--main-min` 之后剩下的宽度），里面是**动态打开的工具标签**（文件、变更、提交图谱、终端，可以一个都没开）。占右列时左缘 `1px` 分割线外加 `--divider-hit-width`（`6px`）拖拽热区（缩到 `<= 150px` 时同样实时收到 `0` 宽、窗口右缘留一条强调色竖线，松手才收起右栏，已打开的标签不动）；窄档时是一层盖住正文的全高抽屉，宽度 `min(var(--panel-width), 92vw)`。背景 `Surface 1`。
    *   **一个标签都没开**：右栏不收起，正文区居中给一份启动清单——每行「图标 + 名字 + 右对齐的浅色快捷键提示」，文件 `Ctrl+Shift+E`、变更 `Ctrl+Shift+G`、终端是 `Ctrl` 加反引号；mac 上把 `Ctrl` 换成 `⌘`，提示里的写法随平台走、与真实绑定同源（`workspace-shortcuts.ts`）。点一行就把那个工具打开；关掉最后一个标签也回到这里，不强行关掉整个右栏。
    *   **`⤢` 右栏最大化**：右栏**盖住正文那一列**（占「视口 − 左栏」），正文列宽归 `0`，不给它留 `--main-min`；左栏照旧按意图摆，两侧的意图位与偏好宽都不动，`⤡` 还原后按原偏好宽恢复三栏。展开期间不渲染拖拽条（拖动会覆盖偏好宽），顶带中格的控件也不渲染（那一列被盖住）；收起右栏同样退出展开；窄档抽屉里不给这枚按钮。
*   **消息动作 (Message Actions)**：用户消息底部靠右是 `22×22` 的复制与回退，每轮收尾处靠右是复制与分叉，复制都排在左边。按钮无边框、无底色；用户消息上的两个默认隐藏，悬停该行才出现，收尾处的复制与分叉默认可见。只有指针落在按钮本身时该按钮才转强调色，悬停整行不影响。复制成功后图标换成对勾并保持 1.2 秒。
*   **应用外壳 (App Frame)**：去掉系统标题栏。顶带（`--chrome-height`，`36px`）与下面的正文行在同一个 CSS Grid 里，用 `subgrid` 共享同一组列轨道；三格宽度取自实占宽 `--col-sidebar`、`--col-panel`（由偏好宽 `--sidebar-width`、`--panel-width` 派生），所以顶带里的东西永远和下面的列对齐：
    *   左栏开关（`SidebarToggle`）：与 `Facet` 字样一起放在顶带左上角 `.chrome-brand`（开关紧贴 `Facet` 右侧），无论左栏展开、收起或拖拽调宽都保持坐标不变、共用同一个外框并在 `panel-left`（展开）与 `square-padding-left`（收起）之间平滑过渡内部竖线，支持原地连续点击；窄档抽屉打开时头部左侧同样以 `Facet` + 关闭按钮对齐在这一位置
    *   左格：侧栏头部（搜索会话与添加项目按钮贴齐右缘）；侧栏展开时这一格保持与外框一致的 `--bg-subtle` 底色，与下方侧栏和右侧顶带融为一体、不画固定底分界线与右分界线；侧栏收起时这一格宽度收到 `0`，随列滑出不占位
    *   中格：左端是当前会话标题（过长省略），左栏收起、拖收或窄档时左端自动让出 `--chrome-sidebar-toggle-clearance` 避开左上角常驻左栏开关；右栏收起时右端通过 `--chrome-panel-toggle-clearance` 为右上角常驻的右栏开关让出位置
    *   右格：工作区的**动态标签** + `+` 菜单 + 右端的 `⤢` 宽展开 / `⤡` 还原，宽度等于右栏的实占宽，展开时左缘用居中的 `14px` 短竖线（`--border-subtle`）与中格区隔，保留通透呼吸感，同样不画底分界线；右栏不在列上（收起、中档被折起、窄档）时这一格不渲染。这一格自己是容器查询的容器，量到的是整列宽，因此横向内边距 MUST NOT 加在这一格上：让出右栏常驻开关与窗口按钮簇的 `padding-inline-end` 写在里面那一行（`.chrome-slot-row`）上
    *   右栏开关（`PanelToggle`）：固定锚在窗口按钮簇左侧（`right: var(--chrome-panel-toggle-right)`），无论右栏展开、收起还是宽展开都保持坐标不变、共用同一个外框并在 `panel-right`（展开）与 `square-padding-right`（收起）之间平滑过渡内部竖线，支持原地连续点击；收起时挂载改动数角标（0 不显示），展开后角标隐藏由工作区标签接手
    *   外壳与色差分隔：整套 `.app` 外壳统一使用 `--bg-subtle` 作为 L 形外框底色，左侧栏与顶部顶带完全融为一体、不画固定分割线；正文主区（`.main`）与右侧工作区（`.panel`）以 `--bg-canvas` 底色、外缘圆角 `--radius-xl`（`12px`）与 `1px solid var(--border-subtle)` 外框描边浮于外壳之上。并排展开时两栏紧贴共用中间一道 `1px` 竖线、间距为 `0`；右栏收起或打开期间两栏分离并各自切换为四角完整圆角，通过同帧 `margin-right` 布局过渡使间距在 `0` 与窗口外框留白 `--space-4`（`8px`）之间渐进变化；`⤢` 宽展开时右栏同样保持四角圆角。左侧分隔条悬停或拖动时沿主区（或宽展开右栏）左缘及左圆角贴边亮起 `1px` 中性描边并在 `--radius-xl` 处渐隐收束（不延伸到顶底平直边框），右侧分隔条悬停或拖动时仅沿右栏左缘竖直亮起 `1px` 中性描边；无边框窗体最外圈另带 `1px` 内框轮廓线（`.app::after`）
    *   窗口按钮：最小化、最大化、关闭三个 `--window-button-width`（`44px`）按钮是右上角的**固定簇**常驻，使用 `10×10` 1px 锐角几何线形并在左侧留一条 `14px` 垂直细线分隔面板按钮，不占列轨道；中格因此用 `padding-inline-end: max(0px, calc(var(--window-controls-width) + var(--space-3) - var(--panel-track)))` 让出这段，右格再自己扣掉整段 + 间距
    *   整条带铺一层 `app-region: drag`，格子里的控件自己标 `no-drag`；双击空白处由 Chromium 处理成最大化切换
    *   档位只看 `.app` 上的 `is-narrow` 类名（判定与断点数值只在 `layout-mode.ts` 一处），样式里不再写档位媒体查询；窄档左格实占宽为 `0`，侧栏头部改由抽屉自己画
*   **工作区标签栏 (Workspace Tabs)**：右栏顶端的一条，只放**已经打开**的工具，按打开顺序排。单个标签高 `--workspace-tab-height`（`26px`）、相邻两条间距 `--workspace-tab-gap`（`2px`）、标签左右内边距 `--workspace-tab-padding-x`（`10px`）、图标到文字 `--workspace-tab-icon-gap`（`6px`）、关闭按钮 `--workspace-tab-close-size`（`16px`）。底色与胶囊圆角（`--radius-pill`）挂在「一条标签」的外壳上：当前项使用扁平 `--bg-active` 底 + `--fg-default` 文字（无描边与阴影），其余为透明底 `--fg-muted` 文字（悬停亮 `--bg-hover`），不可用项压到 `45%` 不透明度。变更带上改动文件数（0 不显示），终端带上开着的终端数（多于一个才显示），主机没有终端能力时终端那一条不可用。语义是 `role="tablist"` / `role="tab"` + `aria-selected`，焦点按游标只落在当前项上，方向键循环、`Home` / `End` 到两头，`Delete` / `Backspace` 关掉当前标签。每条标签右侧一枚圆形关闭按钮（`×`，常态隐藏，悬停或聚焦整条标签时将右端文字渐隐并原地覆盖在胶囊右端，不向右撑宽邻项），中键点标签同样关掉。标签栏末尾固定跟一枚 `xs`（`24px`）圆形 `+`（`WorkspaceTabMenu`，`radius="pill"`）：弹出全部三件工具的菜单，没开的追加并激活、已开的只切过去（图标染强调色），行内带计数与快捷键提示；菜单是 `document.body` 上的浮层（`--z-popup`），`Esc` 时先 `preventDefault()` 再关，`pointerdown` 到别处、改窗口大小也关。标签一律按内容占宽：文字永远在，不折成图标、也不向内省略，放不下时标签栏自己横着滚（滚动条不画，在有内容溢出被遮住的左/右边缘铺 `--workspace-tabs-fade` `24px` 渐隐遮罩；滚轮与触控板都接到横向，当前项切过去时自动滚进可视范围），右端的 `+` 与两枚动作不被挤出去；整列宽窄于 `420px` 时只收紧标签与同排按钮的间距。四件工具全开时末尾那枚 `+` 不再渲染（没有可打开的东西）。折点与实测口径见 `docs/layout.md` §2 / §3 约束 1。
*   **对话导航 (Chat Outline)**：正文右侧的竖轨，距主区右缘 `--outline-inset`（`8px`），宽 `--outline-rail-width`（`36px`），纵向占主区域高度的 10% 到 90%；每条用户消息一根短条，静止 `10×2px`，当前轮次加宽到静止宽度的黄金比例（`16.2px`），指针附近按距离放大到 `22×4px`（半径为 3 条，升余弦衰减，过渡 `--dur-fast`），加宽与放大叠加时总宽收到轨内宽（`30px`）不溢出；短条的尺寸系列都在 `:root` 里（`--outline-pill-*`），组件只写 `--outline-grow`。占位宽度由样式表算死：`--outline-slot = calc(var(--outline-rail-width) + var(--outline-inset) * 2)`，正文自动避让，脚本不再量宽度。悬浮时在竖轨**左侧** `2px` 处显示 260px 宽的预览卡（向左展开，不会被窗口右缘裁掉），两行截断。**唯一的隐藏条件是没有可跳的条目**（少于 2 条用户消息，或用户关掉了它）——与窗口宽度无关，窄屏也不隐藏。
*   **工作区分栏 (Workspace Split)**：**变更视图**是「**预览 + 索引**」这一对，排布按右栏自己的宽度换（容器查询，`docs/layout.md` §2）；文件视图是并排的「编辑器 + 文件树」，不参与这套分栏。
    *   **`≥ 680px` 两栏**：整屏是 `会话栏 | 对话 | 预览 | 索引`。索引栏宽 `--workspace-list-width`（`200–480px`，缺省 `320`，落盘 `facet.workspace.listWidth`），分隔线画在它的左缘（`border-inline-start`），与外层分隔条、窗口右缘都不重叠。**这条分界线可以拖**：命中区 `6px` 且始终透明，悬停与拖动时只把分界线本身染成强调色（不改宽度、不加线，内容不跳）；拖动即时跟手、松手才落盘，预览始终留得下 `280px`，变更页与提交图谱拖一次两边都记住。索引栏顶栏的左缘是收起按钮（`PanelRightClose`），标题随后，右端只留刷新 / 增删统计。收起之后预览向右长满、左缘不动，展开入口（`PanelRightOpen`）落在预览区二级顶栏的最右端（文件是标题行、变更是补丁顶栏），预览为空时挂在空状态卡片里。
    *   **`< 680px` 单栏钻取**：一次只显示一层，满宽。先看列表（变更列表），点改动 / 提交原地切到满宽预览；预览二级顶栏**左上角**是一枚 `←`（随后是路径），点它退回列表——单栏态里两个「收起 / 展开索引」按钮都由样式藏起来，`←` 才是唯一的退路。
    *   变更页的预览是补丁文档。
*   **变更页 (Changes)**：右侧索引栏的顶栏是收起按钮、分支名、`↑N ↓M` 与总 `+N −M`；没有刷新按钮——工作树变了由主机推过来，界面自己重取。下面是按路径分组的目录树：目录行只有折叠箭头与目录名；文件行是文件图标、文件名、`+N −M` 与状态图标（新增/删除/修改/重命名/冲突），二进制显示「二进制」，不显示状态字母。目录不显示增删统计，文件与顶栏显示。点文件把左侧预览切到工作树那一份并滚到对应文件；目标文件已折叠时先展开，重复点同一个文件也会重新定位。索引栏只列工作树的改动，**不再内嵌提交历史**：历史是低频的历史态，归「提交图谱」那个标签，跟这里的高频刷新不是一个节奏。列表本身不内嵌补丁。
*   **文件页 (Files)**：编辑器与惰性目录树在同一层**并排占位**（编辑器 `flex: 1 1 0; min-width: 0`，树 `flex: 0 0 auto`），互不覆盖；底色都是 `--bg-canvas`、无投影，中间一条 `1px Line`。
    *   树宽 `180–420px`（缺省 `240px`，`--file-tree-width`）：左缘一条透明拖拽条改宽度（往左变宽），拖动期间不经过渲染，松手落盘；两端兜底是「编辑器至少留 `120px`」——容器放不下时先压树，右栏 `300` 时树 `180`、编辑器 `120`。
    *   树本身：行高 22px、左侧 8px 起按层级缩进 12px，目录在前；目录行是箭头与名称，文件行是文件图标与名称，悬停与选中用文字色叠加，加载中给省略号，失败给「读取失败」。树顶固定、行在下面滚，滚动容器带 `.scroll-y`——细拇指、始终预留沟槽，与全仓其它滚动区同一套（变更索引栏同理）。
    *   开关：编辑器二级顶栏最右端一枚 `FolderTree`（展开时 `aria-pressed` 提亮），树顶栏左缘那枚收起按钮同样关掉它；收起时整栏不占地方、编辑器吃满整行，树的展开状态与滚动位置都留着。没有选中文件时，空态卡片里也放一枚同样的开关。分栏是常驻的正常流，不再有「按 `Esc` 收起文件树」这回事——`Esc` 留给编辑器自己的交互。
    *   编辑器**不折行**：被树挤窄之后长行由 CodeMirror 自己的 `.cm-scroller` 横向滚动，底部滚动条与全仓同一套细条样式（暗/亮主题下都看得见、都能拖）。顶栏的路径过长时省略，操作按钮不被挤乱。
    *   点文件在编辑器里打开它：标题行左右留 `--editor-gutter-x`（`4px`），代码正文贴工作区边界。
*   **Markdown 预览 (Markdown)**：`.md` / `.markdown` / `.mkd` 打开后默认显示渲染结果，正文按 `--file-preview-width`（`720px`）居中，窗口窄于它时两侧退到 `--file-preview-gutter-x`（`16px`）；标题行多一个眼睛/代码图标切到源码，光标停在渲染结果上时看的是未保存的草稿，不是磁盘那份。源码视图认 GFM（表格、任务列表、删除线）与围栏代码块的语言，标记符（`#`、`**`、`>`、反引号）退成 `--fg-subtle`，行内代码用 `--code-block-fg`，链接地址与引用也压到 `--fg-subtle`，斜体走斜体字形。`.mdx` 不在其中，那是带 JSX 的方言。
*   **编辑 (Editing)**：文本文件**直接可编辑**，没有「先点铅笔进只读 / 编辑态」那一步。标题栏右侧是保存按钮（`Save` 图标，无障碍名称与悬浮提示都写 `保存（Mod+S）`）；没有改动或正在写盘时它是灰的，能不能点由控件自己说。未保存时路径后面有一个强调色小圆点，保存成功把图标短暂换成对勾；冲突时在编辑器上方给一行「文件已在磁盘上改动」加「重新加载 / 覆盖」。Markdown 多一个「渲染 / 源码」的呈现切换（眼睛 / 代码图标）：那是看法，不是权限，切到源码就能改。
*   **提交图谱 (Git Graph)**：右栏的第四类工具，两级视图。**列表**：顶部一条 `32px` 紧凑工具栏（当前分支、已加载的提交数、刷新），下面是满宽的图谱列表——每行固定 `28px`，左留 `10px` 呼吸空隙，左侧是按 `layoutGitGraph()` 算出来的 SVG 泳道（节点圆点 + 直连线 + 分叉/合并曲线，泳道间距 `14px`，最多 16 列、六个颜色循环），中间是提交说明（单行省略，占满剩下的宽度；常规提交前缀如 `feat(ui): ` 弱化为 `--fg-subtle`，突出正文说明），**右端**是引用胶囊（`HEAD` 用强调色、Tag 用 warn 色、本地与远端分支同一套中性底色与细描边，最多 3 个，多出来的折成 `+N`）。作者、短哈希与时间不进这一行——一行放不下它们时被挤掉的是说明本身；这三样由悬浮卡与提交详情页承担。悬停一行给提交悬浮卡（作者、绝对时间、改动规模、**这一条上的 HEAD / 分支 / 远端分支 / Tag**、短哈希与远端链接）——引用那一栏排在改动规模下面，与列表行同一套胶囊与顺序，卡片里铺得开就换行排，不再折成 `+N`。卡片是**分三段**的浮层：外层不垫内边距（`.pop-tip.is-flush`），横向内缩由段自己给（首段 `12px 14px`、两条分隔条 `8px 14px`），段与段之间用 `1px` 分隔线通栏隔开，段内标题 / 说明 / 正文的间距走 `--commit-tip-lead-gap`（`8px`）、行内并列项走 `--commit-tip-row-gap`（`6px`）；纯文字提示仍用浮层默认的 `8px 10px`。底部分页是**触底自动加载**：还有更旧的提交时，列表底部放一个零高度哨兵，滚到离底 `240px` 就按 `skip` 追加一页（每页 50 条），正在取时底部换成一条读取提示；列表里没有「加载更多」按钮。**详情只有一层**：点任意一行就地钻入，直接是**这条提交改到的全部文件的补丁**（文件头吸顶、可折叠、补丁进入视口附近才取）——没有中间的文件列表，也没有单独的概览块，提交说明、作者、时间、改动规模与远端链接在列表里悬停那一行就有。顶栏只有一条：退回图谱（任何宽度都在）、`短哈希 · 说明`、总 `+N −M`、全部折叠与折行，不叠第二行。提交的改动是既有事实：改动栏里没有刷新按钮，只有取失败时才给重试。从详情退回列表恢复原来的滚动位置；`Esc` 依次退出补丁、文件列表、图谱，一层一次，不会顺手关掉右抽屉。历史**只在图谱看得见时才取**：打开图谱、或者工作树刷新过（HEAD 可能动了）才重取第一页。
*   **变更文档 (Changes)**：变更页左侧的预览，也是提交详情。顶部栏是分支（看提交时是短哈希与说明）、`↑N ↓M`、总 `+N −M`、全部折叠/展开与自动折行；正文把所有改动文件放在同一滚动区，每个文件一个 `28px` 吸顶文件头：折叠箭头、文件名、灰色目录、`+N −M` 与状态图标。点文件头折叠/展开该文件；补丁进入视口附近才取，已取到的结果在折叠后保留。补丁行是全宽色带，行号右对齐，长行默认横向滚动，可切换自动折行；补丁正文可以整段选中复制（行号那列不进选区），滚轮落在补丁上时纵向照样滚的是外面那个文档——横向的 `scroll-x` 只关横向串联；二进制、空补丁与截断各有提示。变更页与变更文档都跟着主机推来的信号自己更新：变更页看得见时才订阅当前项目目录（`workspace:/<cwd>` 通道），主机侧按 500ms 合并一波写盘，同一个仓库的探测单飞、跑完冷却 1500ms（提交历史另有一条车道，冷却 5000ms）；工作树变了重取状态，只有 HEAD 或引用动过时才连提交历史一起重取。窗口失焦或隐藏时信号只记一笔不发请求，回到前台才补一次（`focus` 与 `visibilitychange` 走同一个防抖入口）；改动条数超过 5000 的仓库同样暂停自动刷新，等重新聚焦或用户明说要刷新时再探，回到上限以内自动恢复。
*   **终端 (Terminal)**：右栏的终端标签，独占整宽。打开这一页时若还没有终端，就地新建一个；快捷键 `Ctrl + 反引号` 打开它，没有终端时在当前目录新建。切到别的标签时终端只藏起来、不卸载，PTY 会话与回滚都留着；切回来时重新交给 xterm 量一次尺寸（`FitAddon`），右栏拖宽与 `⤢` 宽展开同理。**只有点终端标签上的 `×` 才结束这个会话**：那一下同时关掉 PTY，不留一个没人看的进程。切回终端标签后焦点直接进入终端，键盘输入不用再点一次；滚动条与界面其它地方同一套。
*   **设置窗 (Settings)**：原生 `<dialog>` 打开的一层，尺寸 `min(920px, calc(100vw - 48px))` × `min(660px, calc(100vh - 48px))`，居中，圆角 `--radius-xl`，采用**左右两段式分栏**：左栏通高 `--set-sidebar-width`（`212px`），顶部放「设置」标题，下面是带图标的分类导航（模型、外观、输入、终端，发丝线隔开后再放「关于」）；右栏顶部固定当前分类标题与关闭按钮，下方内容区铺满列宽并独立滚动，减少动效开关用胶囊拨钮（`role="switch"`）。左右两栏、分组卡片与模型列表行统一用 `--bg-canvas` 作为底色，卡片与模型行配 `1px` 描边。遮罩是 `::backdrop`，点遮罩或按 Esc 关闭，页面其余部分在打开期间不可交互，焦点由浏览器收在弹层里并在关闭后还给打开它的按钮。页内按主题分组：组标题在上，下面是一张卡片，卡片里一行一个设置（左名字、右控件）。外观页「通用」组里依次是主题色板、运行中的动效（呼吸 / 扫光）、减少动效。终端页只有「启动」一组：「默认 shell」下拉里第一项是「自动」，其后是主机上报的可用终端（Windows 上是 pwsh 7 / Windows PowerShell / Git Bash / WSL / Command Prompt 里探到的那些，POSIX 上就是 `$SHELL`），选中项存进设置的 `terminal.profile`，新建终端时由主机按它解析路径与启动参数；设置里留着本机没有的标识（换过主机、卸载了某个 shell）时下拉仍显示「自动」，与主机的回落一致。清单读不到时在原地说事实并给重试，不摆一个空下拉。设置没有保存按钮，改动停下 1 秒自动提交，关闭时立刻提交。页面里的下拉（带 `.ui-input` 的 `<select>`）用 `appearance: base-select` 换成界面自绘的菜单：触发器沿用输入框样式，文字在按钮里居中，右缘是一个固定的 chevron-down（展开与收起一个样，不翻面），宽度跟着当前值走、最宽 220px，值放不下时单行省略（与侧栏会话行同一套 `.ell`）；弹层与触发器右缘对齐，比按钮宽时朝左长（左边放不下才翻成左对齐），外观与右键菜单同款（`--bg-elevated` 底、1px 描边、`--radius-lg` 圆角、一层 `--shadow-popover`，超过 320px 在层内滚），当前值用 `--bg-active` 底标出、不画对勾。不支持这个属性的引擎退回系统菜单。
*   **模型页 (Models)**：右侧主栏头部给出当前分类标题「模型」，下面依次是三段，唯一的主动作「添加提供商」（强调色填充，带加号图标）放在「已配置的提供方」分组标题行右侧：
    *   **默认设置**：一张卡片两行，两行都直接写 pi 自己的设置（`settings.json`），新建会话由 pi 用它开局，facet 自己的设置文件里不再存这两项。上面一行「默认模型」，下拉里只有可用模型（`提供方 / 展示名`），写 `defaultProvider` 与 `defaultModel`；pi 里存的模型已经不在可用范围时也照样列出来。下面一行「默认思考档位」，写 `defaultThinkingLevel`，选「由模型决定」就把这一项清掉。下拉的宽度跟着当前值走，不写死。
    *   **已配置的提供方**：组标题带条数（`已配置的提供方 · 4`），只列有凭证的与自定义的。整组是一张圆角卡片，行与行之间是一条 1px 发丝线；每行左边是名字首字母的圆牌（`26px`，取强调色 14% 底与强调色文字），名字（自定义的再带一个「自定义」徽标，内置的不加标记）后面直接是「编辑」，一行放下；只有缺密钥时才在「编辑」左边给一个 6pt 的告警色点（`--dot-warn`），密钥配好的行不加任何标记。行里不放密钥、删除这些按钮，状态也不用文字说。
    *   **可用模型**：与上面同一套卡片行，只列已配置提供方的模型；每行是展示名、`提供方 · 模型标识`（等宽）与一个「测试」。测完在「测试」左边给一个状态点：成功取 `--dot-ok` 并在旁边写往返耗时（`240 ms`），失败取 `--dot-warn`，主机给的原话补在来源那行下面。
    *   **添加提供商**：点页头的按钮打开 `520px` 宽的挑选弹窗，顶部搜索框自动聚焦，只列还没配置的提供方并可搜索；每行只有字母圆牌、名字与「添加」，一行放下——点了关掉挑选弹窗，直接打开这个提供方的编辑弹窗填地址与 API key。底部左侧是强调色文字的「＋ 添加自定义提供方」，右侧是「完成」。
    *   **提供方编辑弹窗**：整页是一份草稿——字段改动、密钥的替换与删除都只改本地状态，点底部的「保存」才一起落盘，点「取消」全部丢掉（「删除提供方」是独立的两步确认动作）。`720px` 宽，圆角 `--radius-xl`，头部是一行标题（`编辑 · DeepSeek` / `添加自定义提供方`）与关闭按钮，底部是一条带上边框的操作栏，中间正文自己滚，保存与取消不会滚出视野。字段自上而下：自定义提供方先是并排的「名称」与「标识」（标识跟着名字自动推出，改过之后不再覆盖），然后是「接口地址」「接口协议」——内置提供方的地址、协议与模型全由 pi 的目录给定，弹窗里不给这几项，要改地址就新建一个自定义提供方；接下来是「密钥」——一块浅底方框，里面就是一个输入框（右边只有已配置时才出现的「删除密钥」）：已配置时占位提示「输入新密钥以更新」，未配置时占位提示「未配置密钥，输入新密钥以更新」。填了新密钥、或者按下了「删除密钥」，都要等弹窗底部的「保存」才落盘（按下的删除按钮变成错误色、文字改成「取消删除」，再点一下收回）；行内没有自己的保存按钮，密钥区里也没有状态点，配没配由占位提示与删除按钮体现；最后是「模型」。自定义提供方的模型是七列网格（模型标识、展示名、上下文窗口、最大输出、图片、思考档位、移除），表头与每行共用一组列宽，右上角并排「从上游获取」与「添加模型」——「从上游获取」由主机拿上面的地址与密钥去打上游的 `/models`（有的网关要密钥才给列表）：地址是裸站点根时并发试 `{根}/models` 与 `{根}/v1/models`（中转站对未知路径回 200 + 前端 HTML，响应不是模型清单就算失败），成功后把可用地址回填进「接口地址」；拉到的模型用 pi 的模型目录补上展示名、上下文窗口、最大输出、思考档位与图片输入（同一标识多来源时与提供方同名的那条优先，其次取档位写得最全的，查不到就留空），同一个标识的行按拉回来的那份整行重写、表里没有的补在后面，没有标识的空行不动；内置提供方的模型由 pi 的目录给定，只列出展示名、标识与上下文窗口。
    *   **图片列**：「收不收图片」一枚勾选框。勾上写 `input: ["text", "image"]`，不勾不写这一项——pi 对自定义模型的缺省就是只收文字，写 `["text"]` 与不写等价；「从上游获取」按快照的 `modalities.input` 自动勾上（全库 1520 个模型里 1058 个标了 image）。这一项决定输入区的加图入口：模型不收图片时选图项置灰、拖拽与粘贴都直接忽略。
    *   **思考档位格**：这一格是按下就开菜单的按钮，格子里写勾到的最高一档（一档都没勾时是一道横线），列的标题是「思考」，所以这一格读作「思考到哪一档」。菜单是一层七档的复选组（`off` / `minimal` / `low` / `medium` / `high` / `xhigh` / `max`），勾上的就是模型支持的档位：写进 `models.json` 时不可用的档位写 `null`，可用的低档不写（pi 的缺省即可用、值等于档位名），`xhigh` 与 `max` 写同名才出现；七档全勾时文件里只多出 `xhigh` 与 `max` 两条，与 pi 自己目录里的形状一致。只勾 `off` 与一档都不勾都表示「这个模型不会思考」，此时只写 `reasoning: false`、不写映射。上游补全按快照里的思考选项填：`effort` 有档位清单就照抄（`none` 即 `off`），带 `toggle` 时补上 `off`，只有 `toggle` 时给 `off` 与 `high`，只写了 token 预算的不造档位、留给用户自己勾。菜单走原生 Popover（`popover="auto"` + `popovertarget`）：它在浏览器 Top Layer 里，不会被弹窗自己的滚动区裁掉，点外面由浏览器收；落点用 CSS 锚点定位（触发器的 `anchor-name` 与菜单的 `position-anchor` 由行键派生的动态名字接上），下方放不下时翻到触发器上方。`Esc` 由菜单自己先吃下（`document` 捕获阶段 `preventDefault()` 再手动收起），否则同一个按键会连带把设置窗一起关掉。
    *   **模型行的校验**：模型行里标识与展示名都不能留空（pi 对 `models.json` 整份校验，空值会让整份里的自定义提供方一起失效），上下文窗口与最大输出填 `0` 或负数按缺省处理。自定义提供方的操作栏左侧是「删除提供方」，按一次变「确认删除 / 取消」，右侧是「取消」与「保存」。
    *   各组只留标题，设置项只留名字与控件，不写说明文字；API key 状态、可用状态都由点与按钮本身表达。
*   **响应式规则**（档位语义与数值的真值在 `docs/layout.md` §2）：
    *   **宽档 (`>= 1120px`)**：三栏同时平铺显示，两侧都可拖宽。
    *   **中档 (`880–1119px`)**：双栏预算折叠——正文加至多一个边栏，两侧都开时按「后打开者优先」折起另一栏（被折起的那一栏点它的开关或标签就换边），正文不小于 `--main-min`（`420px`）；视口回到 `>= 1120px` 时按偏好宽与用户意图无感恢复。
    *   **窄档 (`< 880px`)**：单栏满宽正文，左右两侧都是互斥的全高抽屉，从窗口顶边到底边，带共享遮罩与 `Esc` / 点击外部关闭；抽屉自带 `36px` 顶头（左：侧栏头部与收起按钮，右：标签 + `+` + 收起按钮，右侧让出 `132px` 窗口按钮簇），右上角窗口按钮始终压在抽屉之上、恒定可点。窄档没有 `⤢`（抽屉已经接近满宽），右栏收起时也不在窗口右缘留任何竖轨，入口统一在顶带右上角。
    *   **宽展开 (`⤢`，右栏最大化)**：右栏盖住正文那一列（`视口 − 左栏`），正文列宽归 `0`；不改两侧的意图位与偏好宽，`⤡` 或收起右栏就恢复三栏。它是临时视图，刷新与切进窄档即失效。

## 3. 核心模块与组件规范 (Core Modules)

### 3.1 左侧边栏 (Sidebar - 会话与项目管理)
*   **宽度**：缺省 `272px`，右缘一条 `--divider-hit-width`（`6px`）命中区可拖，范围 `220–420`；这 6px 里只有 `--sidebar-hit-inset`（`1px`）压在列表内容上，其余落在接缝外侧的主区，贴右缘的滚动条照旧可点（伸出去的部分靠宽屏下 `.sb` 的 `overflow-clip-margin` 才不被裁掉）。拖动期间直接改 `--sidebar-width`，松手才提交，宽度与顶带左格同步（与右栏同一套逻辑）。默认值、上下限与夹紧口径在 `sidebar-state.ts`（`clampPaneWidth`，与右栏共用），跟着本地存储走，不进主机设置。命中区悬停或拖动时，沿着主区卡片的左侧边与上下圆角亮起 `1px` `--divider-highlight` 中性描边，不切进顶带也不另叠直线；右栏分隔条悬停或拖动时直接将主栏与右栏之间的 `1px` 细线染成 `--divider-highlight`。拖动期间在 `body` 上铺一层透明遮罩（`.pane-resize-overlay`，`inset: 0`、`cursor: col-resize`），整屏的命中与光标都归它：底下按钮收不到 hover、正文不会被顺手选中，指针滑出分隔条也不会变回箭头；松开或组件卸载时跟着摘掉。
*   **顶部工具栏 (Header)**：应用标题 `Facet` 在左，搜索会话、添加项目、收起侧栏三个图标按钮靠右对齐，按钮边长 `--icon-button-size`（`28px`），这一行上下各 `4px` 让按钮在 `36px` 的顶带里垂直居中，标题与下面的新建按钮、会话行左对齐（都在距侧栏左缘 `10px` 处），按钮距侧栏右缘同样 `--sidebar-edge`（`10px`）；这一行落在窗口顶部那条带里，参与拖动。窄屏抽屉自带一份同样的头部。搜索按钮只负责打开浮窗，输入框不在侧栏里。
*   **核心操作区**：
    *   **新建会话按钮**：占满宽度的沉稳卡片式次级按钮（`--bg-surface` + `--border-default` + `--shadow-control`），左对齐与下方项目过滤器的图标同列，不拿高饱和主色抢夺视觉重心。
    *   **项目过滤器 (Project Filter)**：点击弹出下拉列表组件，可全局搜索项目。带有当前项目标签和相关的主机/上下文信息展示。
*   **会话队列列表 (Queue)**：
    *   **分组**：按时间线分组（"进行中", "今天", "昨天", "更早"）。组标题展示组名及数量。日期组按最后活动时间倒序；"进行中"组只按进入先后排，新开跑的一行出现在组首，已经在跑的几行位置不动——主机推来的摘要时间每一轮都会刷新，照着时间排会让同时在跑的会话互相挤。
    *   **列表项 (Row)**：Hover 时叠一层 `--bg-hover`（前景色 7%），Active（当前选中）叠 `--bg-active`（前景色 14%）并给标题 500 字重、副标题提到 `--fg-muted`；两者都不用左侧强调条或描边。在会话行上右键打开浮层菜单，菜单出现在指针位置并收进视口，里面是重命名、打开所在文件夹（在主机侧文件管理器里打开该会话的工作目录）与删除；点菜单外或按 Esc 收起。全部项目视图里每行分两行：第一行标题，第二行左边项目名、右边相对时间，字号 `--text-xs`、颜色 `--fg-subtle`；单项目视图仍把标题与时间放在一行。两行时行最小高度 `--sb-row-two-line-height`（`44px`），纵向内边距 `--sb-row-padding-y`（`6px`），状态槽对齐第一行。
    *   **状态标记 (Status mark)**：位于列表项左侧的固定槽位（`--status-slot`，`12px` 见方），槽位尺寸不随状态变，标题因此不会左右跳动。五种画法：
        *   运行中：环。三个圆画在一个 SVG 里：闭合的轨道环（30% 透明）、走四分之一圈的弧（90% 透明、圆头端）、中间一个 6pt 的点。半径与描边宽度都从 `--status-ring-*` 算，`cx/cy/r` 当 CSS 属性写；弧的虚线用 `pathLength` 把周长归一成 100 后写成 `25 75`，偏移动画走满 100 正好回到起点。周期 `900ms`，所有环共用文档时间轴的起点，后出现的环与在转的环同步。
        *   等待输入：填色的告警图标（`CircleAlert`，12pt），描边取侧栏底色，圆的轮廓与感叹号从这个颜色里挖出来。
        *   有结果：6pt 填色圆，成功色。
        *   失败：6pt 填色圆，错误色，外面一圈 1pt 透明空隙（`--status-dot-gap`）；空隙透出行自己的底色，行悬停与选中变亮时不会多出一圈暗环。
        *   已完成：6pt 填色圆，中性色加 30% 透明度——弱化但占住左侧导轨，嵌套行不会看起来像项目标题。
        *   颜色直接取 `theme.css` 里的 `--dot-run` / `--dot-warn` / `--dot-ok` / `--dot-err`；`prefers-reduced-motion` 下环不转。
*   **搜索浮窗 (Session Search)**：`⌘K` 或头部搜索按钮打开的一层浮窗，居中偏上（距正文上沿 `12vh`），宽 `min(560px, 100vw - 32px)`，圆角 `--radius-xl`，底色 `--bg-surface`，1px 描边加一层大阴影；遮罩固定在视口上，连窗口顶部那条带一起变暗，点遮罩关闭。顶部是图标加输入框（自动聚焦、`--text-body`），下面按改动时间倒序列出匹配的会话，每条是状态点、标题、项目名与相对时间，当前会话的时间用 `--accent-fg`；上下键走、回车打开、Esc 关闭，最多 40 条，无匹配时给一行「没有匹配的会话」。侧栏里的队列不参与过滤，浮窗关掉之后还是完整的一份列表。
*   **底部区域**：
    *   **页脚 (Footer)**：左侧是主机切换按钮，右端是设置，按钮与顶栏同为 `28px`，左缘与正文对齐（距侧栏左缘 `10px`）；不再显示主机名；主机切换点开是主机清单，列出本机与已添加的远程主机，行内是状态点、名字与 `host:port`，底部「添加主机」。关闭窗口后主机一律留在后台，这里不再给开关与结束主机的入口。

### 3.2 主工作区 (Main - 聊天与编辑器)
*   **顶部导航 (Workspace Header)**：
    *   选项卡容器（对话、打开的文件）。支持横向滚动，隐藏滚动条。
    *   全局滚动条：细的悬浮条，没有外框、轨道与两端的箭头，只剩一条 40% 不透明的拇指，指针落上去提亮；需要完全隐藏的地方用 `::-webkit-scrollbar { display: none }` 覆盖。Chromium 给了 `scrollbar-width`/`scrollbar-color` 会改按标准画并带箭头，所以这边只走 webkit 伪元素。所有会滚动的容器都留出沟槽（`scrollbar-gutter: stable`），滚动条出现时内容不左右跳动。
    *   滚动容器统一走 `ScrollArea`（`packages/ui/src/common/scroll-area.tsx`）：类名 `scroll-y` 给纵向滚动并始终预留沟槽，只横向滚的容器用 `scroll-x`，两个方向都要滚的（Markdown 预览正文、扩展卡片里的预览与预填）用 `scroll-both`，行用 `ScrollRow`（类名 `scroll-row`）承担横向留白。CSS Modules 里的滚动容器同样挂上这三个全局类名——滚动条样式按类名列白名单，哈希后的类名对不上，会退回系统默认的粗滚动条。Chromium 把滚动条画在容器的内边距里，所以占满一整栏的滚动容器**只留纵向内边距**，横向留白交给每一行，滚动条才能贴着容器右缘；行相对容器边缘的留白由 `--scroll-inset` 给出，右侧再扣掉 `--scrollbar-width`，左右才对称。弹层（命令列表、搜索浮窗、项目选择）不套这个约定：它们的留白跟着弹层自己的内边距走。
    *   当前文件激活时，右侧显示编辑器工具（查看模式切换：预览/内容/改动）。
*   **对话流 (Timeline)**：焦点管理 (Accessibility/Focus)：所有按钮、输入框、树状菜单项必须支持 Tab 键获取焦点。弹出项目切换器时，焦点需限制在弹窗内（Focus Trap），关闭时焦点需恢复到原按钮。
    *   **扩展交互卡片 (Extension Prompt)**：扩展发起的确认、选择、输入与多行编辑都显示为输入区上方的一张卡片，位置在排队条与输入框之间，宽度与输入框一致；背景 `--bg-surface`、1px `--border-subtle` 描边、圆角 `--radius-lg`、内边距 `var(--extension-card-padding)`，不使用遮罩。标题取扩展标题的第一段，其余段落作为正文显示并保留换行。选择请求是单选列表：每行 18px 圆圈，选中时圆圈换成强调色圆点、行底色用 `--bg-active`，未选中时「提交」不可用；上下键换选中项，回车或点「提交」提交，Esc 或「关闭」取消。确认只显示正文，输入与多行编辑在标题下方给控件，多行编辑保留完整预填内容与换行。结构化请求在同一张卡片里按题分标签页：标签页写 `header`，缺省时写题号，文字居中；已作答的题目前显示强调色对勾，未作答的题目前显示 `--fg-subtle` 的空心小圆点，当前选中未作答时提高不透明度；左右键换题，每题的选项排在标题与正文下面，单选是圆圈、多选是方框，选项说明用小一号的 `--fg-muted` 文字。题目允许自定义答案时，选项列表最后多一行 `Type something.`，选中后这一行原地换成输入框，单选题输入后清空已选选项，多选题与勾选项一起提交。选项带预览时，在选项列表下方用等宽文本块显示当前选中项的预览，未选中时显示第一项；自定义答案激活时隐藏预览。备注输入框排在最后，回车与「提交」一次交出整组答案。卡片底部右侧是关闭与提交两个按钮。只读端与断线时同一位置显示只读卡片，保留请求内容，不给按钮。同一会话有多个请求时按发起顺序逐个展示，前一个结算后自动顶上。
    *   向下滚动，顶部包含会话标题和 Meta 信息。
    *   **长会话**：每条消息行使用 `content-visibility: auto` 与 `contain-intrinsic-size: auto 64px`，离屏行跳布局与绘制；带 `data-outline-key` 的用户行保持正常渲染，保证对话导航跳到真实位置。
    *   **用户气泡 (User)**：包含提示符（`>`）和文字。
    *   **消息里的图片 (Message Images)**：用户随消息发出的截图、模型直接给出的图片排在正文**上方**：用户行靠右（与气泡同一侧），助手行靠左。一张一个**正方形缩略图**，边长 `--msg-image-size`（64px），几何与输入区待发附件同一套：`--attach-thumb-radius` 圆角、`--attach-thumb-gap` 间距、`border-subtle` 一圈，图片 `object-fit: cover` 铺满整格（比例对不上就裁，不留白），指针 `cursor: zoom-in`。格子里是裁过的，点一张开全局图片预览看整张，组内是这条消息的全部图片。数据就是消息内容里的 base64，拼成 `data:` URL 直接给 `<img>`（`loading="lazy"` + `decoding="async"`），不落盘、不走网络、也不另做占位框——行本身已经按视口裁剪，先挂空盒子只会在图到齐前把高度撑错一次。只有图片没有文字的用户消息不再出空气泡。回退与重试会把这段消息的图片一起带回输入区 / 重发，不再把它们压在正文里当一行 `[Image image/png]` 标记。
    *   **过程行 (Process)**：一次提问里没有正文的那些消息合成一行。收起时是一行：扳手图标 + 标题，标题按这一组做了什么事归类计数，例如「运行了 5 个命令」「编辑了 2 个文件和运行了 3 个命令」；只有思考时是「已思考」。默认收起，收起时没有底色，悬停只让文字由 `--fg-muted` 变到 `--fg-default`。展开后标题才带 `--bg-hover` 药丸底、左侧换成朝下的箭头，下面是左侧 `1px` 竖线的缩进区：竖线落在箭头字形的左缘，行内容距竖线由 `--indent-rail-offset` 给出（缺省 `16px`），竖线相对正文列的位置由 `--indent-rail-inset` 给出（缺省 `4px`，来自箭头字形在图标盒子里的内缩）；行首图标边长 `--indent-rail-icon`（缺省 `14px`）、图标到短名的间距 `--indent-rail-gap`（缺省 `8px`），短名列与输出、思考正文的缩进都由这两项相加得到。
    *   **缩进区 (Group Body)**：一行一个动作，行首是 14px 图标（命令、读取、编辑、搜索、其他），接着是短名（Shell、Read、Edit、Grep 等），再往后是等宽字体的参数摘要，单行省略。点这一行才展开输出，输出没有边框与底色，直接缩进在下面；超过 12 行或 1400 字先折起来给「显示全部」。行悬停不加底色：短名默认 `--fg-muted`，悬停或这一行已展开时变 `--fg-default`。成败只由短名的颜色区分：失败 `--status-err-fg`，被中止而没执行到 `--status-warn-fg`；正在执行的这一行由短名与参数摘要上的扫光表示，行尾不加任何标记，也不写状态文字。
    *   **思考行 (Thinking)**：同一组里的一行，大脑图标 + `Thinking`，点开是正文，正文用界面字体。这一轮没有工具调用时它直接落在答复正文里，与 Markdown 左对齐，收起态的悬停与过程组一致（只变文字颜色，没有底色）。
    *   **工具行**：一行只有图标、短名与参数摘要，点开看输出。脚本类工具（`codemode`）短名是 `Codemode`，摘要取脚本第一行有内容的代码；它在脚本里再调用的工具不参与渲染，对话里只剩「一段脚本」这一行，不再被它调用的工具铺满。
    *   **改动不进对话**：工具结果里的补丁不在对话里单独成行，也不画 diff；要看改动走工作区的变更页。
    *   **展开内容**：就是工具结果原文，与模型看到的那份完全一致——`Script completed` / `Wall time` / `Output:` 前缀、多段文字之间的 `==> text N/M <==` 分隔行、`<console_output>` 包裹行都照原样显示，界面不删改任何一行，也不加 `input` / `output` 这类标题。长输出仍按 12 行折叠。
    *   **图片**：工具结果里的图片块直接画在行下面（不进展开区），用 `data:` URL 交给 `<img>`，不落盘、不另起协议。图片进入视口前后 300px 缓冲区内才挂载 `<img decoding="async">`，之前只画 16:9 占位框；按行宽缩放、限高 320px，**不在行内放大**：点一下开全局图片预览（见下一条）。文本结果照旧收在展开区里。
    *   **图片预览 (Image Preview)**：全仓的图片点一下都开同一层浮层——工具结果里的图、正文 Markdown 里的图（`![alt](src)` 与裸 `<img>`）、消息里随用户发出的图、输入区待发附件的缩略图。浮层是原生 `<dialog>` + `showModal()`（Chromium Top Layer），**整层铺满窗口**：图片按**原始像素**画在正中，默认 100%，超出窗口的部分裁掉，拖拽可以看到四周；小图不为了填满而被拉大，居中显示。整层只盖一层**七成的遮罩**（`--image-preview-scrim`：`--bg-canvas` 取 70%，剩下三成透过去，背后的会话隐约看得见），`::backdrop` 保持透明——两处都上色的话浓度会叠成 `1 − (1−a)(1−b)`，改一个数字另一处跟着变。点图片以外的空白、按 `Esc`、点右上角那枚关闭按钮都关掉它。这一层不走弹层那条 `scale(0.97)` 的进场动画（本来就铺满窗口，没有「从窗口里长出来」这回事），图片自己还有 View Transitions 那次形变（缩略图与浮层大图共用 `view-transition-name`，时长与曲线取 `--dur-enter` / `--ease-enter`；`startViewTransition` 不存在、`data-motion="reduced"` 或系统要求减动效时直接切换）。

        控件只有两簇，都浮在图上、都是 `--bg-surface` 胶囊（轮廓只由 `--shadow-popover` 那条 1px 环给）：**右上角**是下载与关闭，**底部居中**是缩放（减、百分比、加，百分比等宽数字），两簇到窗口边缘的距离都是 `--image-preview-edge`。其余动作走键位与手势：滚轮以指针为中心缩放（`25%`–`500%`，监听器显式 `passive: false` 拦下页面滚动）、超出窗口后按住拖拽平移（指针形状 `grab` / `grabbing`）、双击在 100% 与适应窗口之间切、`+` / `-` 放大缩小、`0` 回到 100%、`←` / `→` 在同一组图片之间翻（多张时不额外摆箭头）、`Esc` 关闭。同一组多于一张时组是：工具结果那一行输出的全部图片、正文那一段消息的全部图片、消息里那一条的全部图片、输入区待发的全部附件。
    *   **参数摘要**：一行放不下就截断。鼠标在摘要上停留 0.5 秒才用弹窗给出没截断的完整参数（扫过去不弹），脚本类工具给整段代码；摘要没被截断时不弹。弹窗铺在窗口上（`position: fixed`），不参与行内排版；参数长过弹窗高度时可在弹窗里滚动，指针移进去不会收起，离开 0.3 秒后才关。
    *   **流式状态**：回合还在跑时，组标题与正在执行的工具行用同一套动效表示在跑，落在文字上，不再另加状态点。只要会话仍在推进，组标题就持续播动效——两次模型调用之间、工具执行期间没有流式项时也不停。缺省是呼吸：文字保持 `--fg-default`，`opacity` 在 0.45 与 1 之间按 `--live-cycle`（1.6s）循环（只改不透明度，由合成器执行，文字不参与重绘）。设置里把「运行中的动效」改成「扫光」后换成 `background-clip: text` 的渐变带扫过（`--fg-muted` 打底、`--fg-default` 作亮带），同样按 `--live-cycle` 循环，观感更明显，但逐帧重绘文字。会话状态点的闪烁也取同一个 `--live-cycle`，场上的几处动效步调一致。两种都随回合结束即停；`prefers-reduced-motion: reduce` 下都不播动画，文字停在 `--fg-default`。
    *   **上下文摘要**：压缩期间在消息流末尾显示图标与「上下文摘要」，两侧是分界线，文字使用运行中的动效设置，减少动效时保持静止。压缩条目按 `Entry.id` 固定位置，显示为同名分界，默认收起；点击或用键盘展开后显示完整 Markdown 摘要。历史记录与实时记录共用这一显示方式，多次压缩各自保留分界。取消或失败时收起动效行，完成分界只来自已有的压缩条目。
    *   **富文本 (Prose)**：支持 Markdown 渲染和行内代码块。
    *   **代码块 (Code)**：带有语言标签和“复制”功能（Hover唤出），支持语法高亮。
    *   **变更总结 (Changes)**：展示文件修改的统计（新增行数、删除行数）。
    *   **收尾行 (Turn Footer)**：这一轮结束时一行，左起复制、分叉，右边写这一轮的工作时长，格式与 paseo 一致：`工作了 7s`、`工作了 3m 16s`、`工作了 1h 5m`；还在跑时由界面自己计时。
*   **错误提示 (Error)**：一层 `--status-err-bg` 浅底、`--radius-md` 圆角、`var(--space-5) var(--space-6)` 内边距，不描边；左上是 `--icon-lg` 的警示图标，固定在列首不参与收缩，不写「出错」二字。正文用 `--fg-default` 与正文字号，`overflow-wrap: anywhere` 让长串报错（JSON、请求标识）在任意位置断开。动作是「重试」与「复制详情」两个文字按钮，排在正文下方，悬停转 `--fg-default` 并加下划线。
*   **输入框区域 (Composer)**：
    *   固定在页面底部。
    *   **引用区域 (File Reference)**：如在代码中选择了某几行，会在输入框上方显示引用的文件和行号标签。
    *   **输入域 (Rich Text)**：可编辑区域的容器外边框为 `Line Strong`；聚焦时（容器里任何一个控件拿到焦点）边框变为 `Accent`，外面再罩一圈强调色的淡光晕，可编辑区自身不另画描边。高度两行起步，跟着内容向上长，最多十四行；再多就在框内滚动，滚动条与界面其它滚动区同一套。占位符贴在首行同一处，随会话状态与发送键位换文案（`输入消息,回车发送` / `输入消息,Shift+回车发送` / `输入消息,回车插入当前轮次`）。
    *   **输入域 (Plain Text + 胶囊装饰)**：底层采用 CodeMirror 6，文档真值始终是纯文本字符串——不渲染标题、粗斜体、围栏代码块或引用块，粘贴或手敲的所有字符（`*`、`_`、`~`、`` ` ``、`#`）原样展示与发送，永远零转义。仅保留两类原子胶囊装饰（`Decoration.replace` + `atomicRanges`）：文首落定的 `/命令` 与文中匹配已知路径的 `@文件`（整块跳过、整块删掉、点击 `@文件` 打开对应文件）。行首输入 `1. 内容`、`- 内容` 或 `* 内容` 并按换行键时，自动递增序号或续写列表前缀；在空列表项（如 `2. `）再按换行时自动清除前缀退出列表。两处补全（行首或空白之后的 `@` 列文件、文档最开头打 `/` 列命令）复用同一个 `OptionList` 浮层挂在输入区外框正上方；撤销栈与选区按 `draftKey`（会话）隔离缓存（最多 50 份）；`↑`/`↓` 支持在空输入区或浏览态边界回溯已发消息。
    *   **操作栏**：左侧是「+」添加菜单与两个芯片——模型芯片显示模型名，思考芯片显示大脑图标加档位取值（Off 到 Max，不翻译）；两个芯片默认没有底色，悬停或展开时才有 `--bg-hover` 底与下拉箭头（收起朝下、展开朝上）。右侧是上下文用量环与一枚 `--control-md`（`32px`）的图标按钮：有内容要发时是发送箭头（运行中即排队），这一轮在跑而没有内容可发时换成停止——同一个方框、同样的 `--radius-lg` 圆角（比输入区的 `--radius-xl` 收一档，内外同心），中间换成方块，两种形态互相替换，位置不动。
    *   **发送在途 (In Flight)**：草稿要等主机确认「这条用户消息已进入对话」才收，慢回执期间输入区看起来仍然有内容可发。所以「本端还有一条没被确认的一轮发送」是一件独立的界面状态：它是客户端的记账（`SessionState.hasPendingSend`，只算 `chat/turnStarted` 这一路，排队那条只进队列不算），派发时同步写、回执/被拒/断线重连/会话释放时清掉；输入区据此把发送按钮置灰，回车也不发第二条，同一个草稿的图片编码在这段时间里只跑一次。切换会话时按会话各算各的：会话 A 在等回执，切到没有在途的 B 照样发得出去。这一路只挡界面重复提交，主机侧的 `(clientId, clientSeq)` 幂等保持不变——两次点击本来就是两条不同序号的动作。按住回车的 `repeat` 事件一并拦掉，既不发送也不补换行。按钮在途期间仍是发送（不可点），不换成停止。

### 3.3 编辑器视图 (File View)
在文件标签里点开一个文件，工作区就是它的预览（单栏时占满整宽，两栏时在左侧）。
*   **行号区**：固定在左侧，等宽数字，文本颜色较弱。
*   **源代码区**：横向防溢出。支持 `token` 级别的语法高亮（Keyword, String, Number 等）。Markdown 按 GFM 解析，围栏代码块内嵌语言着色。
*   **Markdown 预览**：`.md` 的默认形态，渲染交给对话区同一套 `markstream`，只是不出流式动画；编辑仍然只发生在源码视图。
*   **Diff 模式**：差异行整行背景色变更（绿底/红底），并在行号旁用 `+` 或 `−` 标识。
*   **底部信息栏**：绝对路径面包屑，所属节点，语言，编码，以及只读状态。

### 3.4 右侧面板 (Panel - 工作区文件)
*   **顶部 Tabs**：在“文件 (Files)” 和 “改动 (Changes)” 之间切换。带徽标数字提示。
*   **项目信息**：当前项目名与所属主机。
*   **文件树 (File Tree)**：
    *   带有即时过滤的搜索输入框。
    *   层级缩进公式：`padding-left = 4px + (深度 * 12px)`。
    *   文件夹前带三角 Chevron 图标（展开时旋转 90 度）。
    *   被修改过的文件右侧带黄色的“已修改”标签。
    *   支持键盘上下箭头导航，Enter/Space 展开或打开文件。
*   **改动列表 (Changes List)**：
    *   平铺展示被修改的文件。
    *   显示独立的新增 (`+42`) 和删除 (`-18`) 的等宽数字统计。

### 3.5 轻提示 (Toast)
操作结果与后台事件的临时反馈，用完即走，不打断当前活动。

*   **位置与容量**：固定右下角，离窗口右、下各 `--toast-edge`（`16px`）；宽 `--toast-width`（`320px`），新的排在下面，最多同时 3 条，超出的丢最旧的。整块只占自己的盒子，空白处不挡鼠标。
*   **等级靠样式表达**：左侧 `3px` 色条与行首图标区分——成功取 `--dot-ok`、告警取 `--status-warn-fg`、失败取 `--status-err-fg`，信息用中性色；文字只写事实（哪份文件、什么原因、谁的退出），不写「错误」「成功」「失败」这类标签。
*   **内容**：同一句话重复出现只留一条，右侧浮现次数；长文本折行，不撑破 `320px`。
*   **不带操作**：提示只说事实，要动手的事回原来的地方做（比如再点一次加号菜单新建终端）；右上角只留一个关闭按钮。
*   **计时**：成功 `3s`、信息 `3.5s`、告警 `5s`、失败 `6s`。指针停在提示上或焦点落在按钮上时暂停，离开时补回暂停的时长；每条都能点右上角的关闭按钮立刻收掉。
*   **进动效**：从下方 `6px` 处淡入，`var(--dur-slow)`（`180ms`）；`prefers-reduced-motion` 时只留淡入。
*   **可访问性**：整块是 `role="status" aria-live="polite"`，读屏在空闲时念一遍，不抢焦点。
*   **谁用它**：后台事件（主机侧的 `chat/notice`、pi 插件 `ctx.ui.notify`）与终端创建失败的说明。复制、引用这类瞬时动作自己给反馈（复制按钮的图标变对勾），不弹提示。需要用户决策的走弹层，需要一直看得见的走页脚，可重试的关键失败走错误条。
*   **层级**：`--z-toast`（`200`），是 `:root` 里最高的一档，压在行内弹层（`--z-popup` `60`）、悬浮提示（`--z-tip` `90`）与拖拽遮罩（`--z-drag-overlay` `95`）之上；刻度与成员见 `docs/layout.md` §4。弹窗不走这组值——原生 `<dialog>` 在浏览器 Top Layer，轻提示被它压住时不弹。

### 3.6 Diff 面板的结构 (Diff Panel)

补丁在变更页、提交详情与单文件视图里是同一份实现（`git-patch.tsx` + `diff-lines.ts`）。

- **四列固定网格**：旧行号 `--diff-gutter-old`（48px）、新行号 `--diff-gutter-new`（48px）、
  记号 `--diff-gutter-sign`（24px）、正文 `minmax(0, 1fr)`。增行缺旧行号、删行缺新行号，
  缺的那格留空但列宽不塌，四列永远对齐。正文列下限是 `0`，超长 token 顶不破容器。
- **三层视觉**：整行淡底（增 `--diff-add-fg` 15%、删 `--diff-del-fg` 10%）+ 最左一条 3px
  实色竖条（`--diff-add-bar` / `--diff-del-bar`）+ 行号列在增删行里透明，底色一路贯通到面板
  最左缘。上下文行的行号列压一档 `--bg-subtle`，悬停时整行与行号列一起切到 `--bg-hover`。
- **前景色不跟着走**：增删行的文字仍是 `--fg-default`，词级高亮只抬底色——深色主题下把文字
  也染成红绿会掉对比度。
- **折行**：`data-wrap="true"` 时正文 `white-space: pre-wrap` + `line-break: anywhere`，
  行号与记号列锁住 `--leading-code-block`，不跟着正文折行涨高；不折行时正文 `white-space: pre`，
  横向滚动交给 `.scroll-x`。
- **代码度量**：整块共用 `--text-xs` 字号、`--leading-code-block` 行高、`tabular-nums` 与
  `tab-size: 4`。
- **文件头**：`--control-lg`（40px）高、吸顶（`position: sticky; top: 0`）并 `isolation: isolate`；
  整行就是折叠开关（一枚铺满的按钮，不用容器 `onClick` + `stopPropagation`）。文件名
  `--fg-default` + `500`，路径前缀压到 `--fg-muted` + `400`。
- **高对比度**：`prefers-contrast: more` 下增删行补 1px 上下轮廓线，不单靠色相区分。

### 3.7 选中文字的右键菜单 (Selection Menu)
正文里选中的文字右键时就地弹出一层小菜单，浮层层级与标签栏的右键菜单同档。

*   **范围**：整棵工作区只挂一份，凡是能选中文字的地方都管；已经自带右键菜单的地方（侧栏行、标签栏）自己先拦下，不会叠出两份。
*   **项**：`--text-menu-width`（`168px`）宽，每项高 `--control-sm`（`28px`，几何来自 `common/ListRow.tsx` 的菜单档），只有文字；有选中内容时至少有「复制」，选区落在对话正文里时多一项「引用」。
*   **落点**：贴光标展开，量过自己的尺寸之后收进窗口，离边缘留 `--text-menu-edge`；点外面、按 Esc、页面滚动或改窗口大小都收起，打开后焦点在第一项。
*   **引用**：选中的文字逐行做成引用块（逐行一个换行节点）接在草稿末尾，引用下方另起一个空段落并把光标放进去，接着写自己的问题。这一步由编辑器的命令式句柄直接插节点完成，不再把草稿拼成字符串整份重载；句柄不在时才退回字符串拼接。

## 4. 关键交互状态要求 (Interaction Guidelines)

设计实现时必须保证以下交互逻辑的完整性：

1.  **组件溢出 (Overflow)**：文件路径、项目名称等长文本必须处理文本截断，统一使用单行省略号 (`text-overflow: ellipsis`)。
2.  **状态互斥 (State Toggling)**：
    *   设置页里的主题会改写根节点的 `data-theme`，配色按此选择变量组；代码配色同时随深浅切换版本。
    *   右面板的隐藏与显示会改变整体 Grid 的列数分配或触发弹窗定位。
    *   对话输入时的“引用文件”，可通过在代码编辑器中点击行号（支持 Shift 多选）触发引用标签生成。
3.  **浮出层定位 (Popover Positioning)**：项目选择下拉菜单需自动计算上下可用空间。如果底部空间不足且顶部空间充足，菜单应当向上弹出（底对齐），防止遮挡视口。
